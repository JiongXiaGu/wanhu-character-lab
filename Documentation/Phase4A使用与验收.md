# Phase 4A · 劳动与射箭

## 使用

拉取已合入版本后，双击 `Start-Local.cmd`，或执行 `npm ci`、`npm run dev`。本轮候选在 PR #5 中执行验收，是否已合入以 GitHub PR 状态为准；本文不以候选提交代替验收结论。

左侧“动作库”分为“射箭”与“搬运与生产”。点击动作生成对应预览道具；点击下方待机、行走等基础动作退出工作预览并恢复原穿戴。

| 分组 | 可播放入口 |
| --- | --- |
| 射箭 | 完整射箭、搭箭拉弓、保持瞄准、抬高瞄准、压低瞄准、放箭收势、取消瞄准 |
| 拾放/负重 | 拾起木箱、放下木箱、抱箱待机、抱箱行走、扛木行走、背柴行走 |
| 生产/运输 | 推独轮车、拉车行走、双手锄地、单手锤击 |

完整射箭为单次流程，结束停帧；“重播动作”再次执行。“搭箭拉弓”结束保持满弓，可分别检查“保持瞄准”“放箭收势”“取消瞄准”。瞄准不会自动放箭，取消不会触发释放。

拾起末帧与抱箱待机、放下起点一致。步行/推拉/工具劳作循环。它们暂时是可选择的原地片段，不是已接入世界导航的自动搬运任务。

暂停、变速、拖动进度和重播可用于检查。定位只还原画面、不生成逻辑事件；真实结束仍保留本次事件计数。

“握点检查”显示绿色目标和金色掌心。正/侧/背/三视图、结构布线和骨骼叠加继续可用。人体与工作道具分开统计面数。

动作不依赖职业：弓手戴农户草帽仍可拉弓。工作期间临时隐藏被占用的原手/背槽，不修改原始 Recipe 或导出；退出后恢复。取箭、道具切换是预览，不是游戏库存系统。

## 自动检查

```sh
npm run check:mesh
npm run check:actions
npm run build
```

动作测试覆盖 17×3×61=3111 采样帧，以及握点、弓弦、20 骨骼、脚底、蒙皮三角形、循环首尾、单次/保持、暂停/seek/跨帧事件和接缝。基模检查保留原有 12 人物变体和 1152 个姿态样本。

截图任务为 `Character Action Screenshot Review`，文件 `.github/workflows/screenshot-review.yml`。产物 `character-action-screenshots` 中包含基线 `review/`、动作 `review-actions/`、JSON/HTML 报告和日志。默认保留 7 天；重要验收截图应及时保存。

17 个动作均有正/侧/背/布线和独立关键相位矩阵。释放前后不是同一张姿势图。额外检查真实播放、保持/取消、单次末帧、定位无事件、DIY、身高体格端点与移动布局。

## 本次回归发现与修正

- 第一轮 CI 发现新增 bow 道具没有加入穷尽型锚点表，修正注册后编译通过。
- 第二轮 CI 发现矮小体型抬高瞄准时手超出可达距离。修正为根据实际骨长限制握点，不放宽 12mm×身高比例的门槛。
- 代码审查发现释放后的右手不应跟随回弹弓弦，改为独立向后缓冲与收势。
- UI 区分循环、单次、持续保持，动作数量来自注册表，不再固定显示 09。

最终截图的实际检查与运行记录需绑定具体提交 SHA；未查看新版本图片前不能标为“视觉通过”。

## 当前限制

没有世界导航、库存/资源业务、跨动作连续装卸状态机、通用动画分层混合或任意姿势平滑中断。车轮按预览速度旋转，尚未接实际行进路程。

射箭是标准方向的完整演示；高低瞄准为有限角度姿势变体，尚未将高低角连续带入发射。取箭为示意，不是背部箭袋真实抽取。飞行箭不是独立世界投射物，没有伤害与真实弹道。

固定 20 骨骼、最多两个非零权重、运行时生成均保留；Unity Crowd、LOD、万人性能、五指、布料/宽袖/长袍仍未实现。
