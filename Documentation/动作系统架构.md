# 动作系统架构 · Phase 4

## 目标

当前人物系统已经完成：

- 连续 Low Poly 人体
- 固定 20 Bone Skeleton
- Slot-based 装备
- 基础 Locomotion

下一阶段不直接堆职业动画，而是建立可复用 Action System。

目标：

- 农民锄地
- 居民搬运
- 工匠生产
- 商队运输
- 弓箭战斗
- 剑盾战斗

全部共享同一套动作语义。

## ActionDefinition

动画不应该直接绑定职业。

推荐数据：

```text
ActionDefinition

├── id
├── MotionClip
├── BoneMask
├── PropSocket
├── RootMotionPolicy
└── Events
```

例如锄地：

```text
HoeGround

Motion:
ToolSwingTwoHand

Prop:
Hoe

Sockets:
LeftHand → GripA
RightHand → GripB

Event:
42%
ToolContactGround
```

---

## Interaction Anchor

人物动作不直接写死世界坐标。

道具提供接口：

```text
PropDefinition

├── LeftGrip
├── RightGrip
├── InteractionPoint
├── AnimationHint
└── Events
```

例如独轮车：

```text
Wheelbarrow

├── LeftHandle
├── RightHandle
└── PushPoint
```

角色只需要匹配 Socket。

## 第一轮视觉验收

视觉验收只使用 GitHub Actions 截图 Artifact，不做 Visual / Vercel 部署。

每个已实现动作必须生成：

```text
front
side
back
cage / wire
keyframe sequence
```

新增 Motion / 可播放 Action 时，必须同步更新自动截图矩阵；没有截图覆盖时 CI 不允许通过。

检查：

- 手是否握住工具
- 肩肘膝是否正常变形
- 道具是否穿模
- 动作循环是否连续
- 同一 Skeleton 是否可复用

GitHub Actions 必须自动生成截图。

## 连续执行规则

新对话接手 Phase 4 后，不要每完成一个动作就停止等待用户说“继续”。

一个阶段的正确闭环：

```text
实现一组动作
→ check:mesh / build
→ GitHub Actions Playwright 截图
→ 下载 Artifact
→ 实际查看 Front / Side / Back / Cage / Keyframes
→ 修复穿模、姿势、方向、Socket、蒙皮问题
→ 重跑截图
→ 达到可验收质量
→ 再通知用户
```

只有出现需要用户选择的美术方向、权限问题或无法自动判断的设计冲突时才提前停下。
