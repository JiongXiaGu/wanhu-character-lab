# 动作系统架构 · Phase 4A

## 版本与范围

当前第一轮实现九项：拾箱、放箱、抱箱行走、扛木行走、背柴行走、推独轮车、拉车、双手锄地、单手锤击。沿用已验收的连续人体、20 Bone ID、最多两个非零权重和 Recipe V4 DIY。没有重做人体，也没有引入布料求解器、外部人物或动画资产。

| 动作 ID | 表现与道具 | 播放方式 | 第一轮事件 |
| --- | --- | --- | --- |
| pick | 屈膝拾起木箱，结束保持抱箱 | 单次 2.8 秒 | grip 38%，load_ready 95% |
| place | 抱箱下放、落地、松手、站起 | 单次 2.8 秒 | set_down 60%，release 66% |
| carry_front | 双手抱箱行走 | 循环 1.3 秒 | 无 |
| carry_shoulder | 右肩扛木、右手支撑、左臂配重 | 循环 1.3 秒 | 无 |
| carry_back | 背架柴捆、双手扶带、前倾行走 | 循环 1.3 秒 | 无 |
| push | 双手推独轮车 | 循环 1.3 秒 | 无 |
| pull | 车在身后，人物面向 +Z 拉车 | 循环 1.3 秒 | 无 |
| hoe | 双手举锄、挥落、触地、收锄 | 循环 2.1 秒 | tool_contact 52% |
| hammer | 右手锤击工件，左手置于安全侧 | 循环 1.5 秒 | tool_contact 52% |

此表是第一轮范围，不表示挑水、推磨、划船、战斗、射箭已经完成。

## 内容与执行分层

- `actions/catalog.ts`：纯数据 ActionDefinition，时长、循环、分类、占槽、事件、阶段、审查时刻。
- `actions/kinematics.ts`：构建期解析两段 IK；根据真实绑定长度求肩肘腕和髋膝踝，手掌偏移与腕骨分开。
- `actions/bake.ts`：统一求值人体、道具和握点，60 Hz 采样成 Clip。固定站姿/行走是下半身原语；搬运姿势覆盖上半身。当前 mask 表示构建时的组合策略，不是已经完成任意运行时 BoneMask 混层。
- `actions/props.ts`：程序生成木箱、原木、柴捆、独轮车、锄头、锤和工作台。道具自身节点不是人体骨骼。
- `actions/player.ts`：Clip 播放、单次/循环、道具绑定、事件游标和调试点。
- `v3/rig.ts`：标准 Three.js SkinnedMesh 适配；工作播放器通过公开 mixer 接口播放独立工作 Clip，不改变旧 Motion 语义。

人体局部骨骼旋转、Hips 位移、WorkObject 位移/旋转在同一个 Clip、同一时间轴采样。正式人物顶点仍由 GPU 蒙皮；不是每帧重建人物网格。解析 IK 在构建/测试时运行，不在正常播放帧中运行。握点显示是调试路径。

## 坐标、接触和道具

+X 为右，+Y 为上，+Z 为前。所有内容先按 1.76 米标称人物定义，身高统一缩放，IK 使用当前人物实际绑定点与骨长。

手掌中心不是 Hand 骨骼原点：握持使用 Hand 局部掌心偏移。道具握点与同一动作求值器中的目标一致，测试通过骨骼世界矩阵重建掌心再测误差。

推车/拉车是原地工作动画。车轮按标定行进速度和半径连续转动，使用累计时间，不能在每个步态循环重置角度。演示没有导航位移；Unity 应用实际行进距离驱动车轮。拉车不是倒播推车：车位于身后，人物仍面向 +Z。

道具预算与角色预算分列。角色仍一个 SkinnedMesh；车/工作台/拾放物是外部交互对象，允许独立 Renderer，不能声称整个交互场景一个 Draw Call。停止动作后销毁道具资源。

## Slot DIY 与临时占用

ActionDefinition.occupied 指明工作时使用的左右手/背槽。visibleRecipe 创建预览副本、暂时隐藏冲突装备，不改变 Recipe V4，不修改 preset、不清空用户原始 Slot。离开劳动动作回到基础动作后恢复剑盾、弓、箭袋等原配置。头饰、衣服和配色保持可编辑。

## 时序与事件

- Pick/Place 使用 LoopOnce，完成后保持最后姿态；“重播动作”明确回到开头。
- 其余工作动作首尾循环；道具与手部同步。
- 正常前向播放跨过事件点才触发事件。暂停、逐帧定位、反向拖动不触发生产进度。
- 从当前位置跳过多个事件/循环时，按跨越次数和先后顺序返回事件。
- 重播清空事件计数；UI 的事件记录是调试信息，尚未连接游戏资源/生产逻辑。
- 动作选择暂不做通用带道具跨动作混合：直接进入确定的示例初态，避免 Blend 时握点漂移。跨动作物品状态机是后续 Phase 4B 工作。

## Unity / GPU 迁移边界

可共用 ActionDefinition、Socket、事件时序、人体骨骼语义和采样数据。Three.js Clip/Mixer 是 Web 适配层，不能当作 Unity API。

不同身材的骨长和逆绑定矩阵不同，本轮按实际身材烘焙；未来 GPU 缓存键至少包含 SkeletonVersion + BindProfileKey + ActionId。不能仅凭 Bone ID 一样就让不同骨长直接共用同一套最终蒙皮矩阵。可共享局部运动规则，但需要按绑定配置组合矩阵。

道具是独立交互对象。拾放的游戏所有权转移应由事件控制；本轮使用同步采样的道具变换验证可见接触，没有声称已实现 ECS 交互状态机。劳动持物动作可预烘焙成常用组合；远景优先预烘焙，不强制每个 NPC 实时 IK。

## 验证和截图门槛

`npm run check:mesh` 保留旧基模与步态检查。

`npm run check:actions`：九项 × 三种体型；每项检查 61 个采样姿态；骨骼合法、网格不重建、手掌/握点误差、三角形非退化、脚底范围、道具预算、循环首尾、单次停帧、跨帧事件、定位不发事件、穿戴恢复。

`Labor Action Review` GitHub Actions：先检查/构建，再用 Chromium 真实 WebGL 渲染。每项都生成正视、侧视、背视、结构线，以及六个关键帧，合计至少90张动作图；另有握点叠加、DIY 大体型和移动端。生成 `review-actions/index.html`、`report.json` 和测试日志。必须打开每项关键图人工检查；截图任务成功不等于美术通过。

算法检查只覆盖指定指标，不证明全体型/任意动作组合永无穿插；更大动作和新服装仍需追加视觉测试。
