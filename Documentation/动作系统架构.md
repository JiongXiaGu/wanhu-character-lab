# 动作系统架构 · Phase 4A

## 当前范围与三轮规划

第一轮实现九项：拾箱、放箱、抱箱行走、扛木行走、背柴行走、推独轮车、拉车、双手锄地、单手锤击。沿用已验收连续人体、20 Bone ID、最多两个非零权重和 Recipe V4 DIY。

4A 验证 Pick / Place / CarryFront / CarryShoulder / CarryBack / Push / Pull / ToolSwingTwoHand / ToolSwingOneHand。它们不是职业专属 Clip：动作与 Slot 配方分开。

4B 复用上述原语，增加挑担、播种、收割、砍柴、扫地、推磨、划船等，并完善 Pick → Carry → Place 的连续物品生命周期。

4C 验证 Raise / Draw / Hold / Release / Recover、瞄准、剑盾、枪刺和受击。女性体型、LOD、Unity Crowd 不包含在本轮完成范围内。

## 内容与执行分层

- `catalog.ts`：纯数据 ActionDefinition；分类、时长、循环、占槽、事件、阶段、审查相位。
- `anchors.ts`：道具局部 Grip / InteractionRoot / ToolContact，不能与腕骨原点混淆。
- `kinematics.ts`：基于真实绑定骨长的构建期两段解析IK和手掌偏移。
- `bake.ts`：统一求值人体、道具、握点，60Hz采样成Clip。站立/行走是下半身原语，负重与工具姿势修改上半身。mask目前表示构建期策略，不宣称已完成通用实时BoneMask叠层。
- `props.ts`：全部运行时建模，车轮使用道具节点而非新增人体骨骼。
- `player.ts`：单次/循环、事件游标、重播、占槽预览、资源释放。
- `v3/rig.ts`：Web SkinnedMesh适配，原Motion/Skeleton语义不变。

Local Bone Rotation、Hips Position、WorkObject Position/Rotation在同一个Clip、同一时钟播放。主体仍GPU蒙皮，不逐帧重建Mesh；解析IK在构建/测试期运行。结构线和握点属于调试路径。

## 接触、时序和DIY

+X右、+Y上、+Z前。标准体型1.76米，道具局部尺寸随身高缩放，IK使用当前体型真实骨长。手掌偏移和腕骨原点分开；测试由骨骼世界矩阵还原掌心并测量握点误差。

推/拉均为原地动作，导航负责世界位移。车轮采用累计时间，不在每个步态循环清零；Unity应改为实际行进距离/半径。拉车把车放在身后，不通过倒播推车实现。

ActionDefinition.occupied仅临时隐藏冲突手/背装备，不修改Recipe V4。退出工作回到基础动作后恢复原配置。头饰、衣服、身材、配色仍可编辑。

Pick/Place使用LoopOnce，结束保持姿态。正常前向播放跨过事件点才发送事件；暂停不发事件、不清除既有计数；主动seek不触发生产副作用。重播重新开始并清空调试游标。

本轮道具所有权是演示状态，尚未接入游戏资源/AI。跨动作物品生命周期和任意带道具混合需要在4B实现。

## Unity与预算

可迁移：ActionDefinition、Slot、Grip/Socket、事件时序、采样数据与20骨骼语义。Three.js Clip/Mixer不是Unity接口。

不同体型的骨长/逆绑定矩阵不同，本轮按体型烘焙。未来最终蒙皮矩阵缓存键需SkeletonVersion + BindProfileKey + ActionId，不能只按同一Bone ID共享所有体型矩阵。远景优先预烘焙常用组合，不强制每NPC实时IK。

角色和道具分别统计面数。独轮车、工作台、拾放物属于独立交互对象，允许独立Renderer，不能宣称整个场景一个Draw Call。场景与道具材质/Geometry在退出时释放。

## 唯一视觉验收路径

完整保留main截图规范：**不部署Visual/Vercel/Preview Site**。`vercel.json`保留`git.deploymentEnabled=false`；runner内localhost只用于Playwright，不是外部部署。

流程：阅读 → 实现一组动作 → 自动检查 → Actions截图 → 下载Artifact → 实际审图 → 修正 → 重跑 → 达到可验收后合入main。无需用户逐次回复“继续”。只有方向决策、权限或无法安全判断的阻塞才询问。

基础Motion矩阵在 `scripts/review-v3.mjs`，由 `check-review-coverage.mjs` 守卫。

劳动Action矩阵在 `scripts/review-actions.ts`，直接枚举WORK_IDS并核对ACTIONS完整性；每个Action必须有Front/Side/Back/Cage和六个关键帧。循环必须包含0/25/50/75%，单次覆盖起始/主要事件/恢复，漏图或缺动作CI失败。所有图必须显示实际道具。

`Labor Action Review` 先执行旧check:mesh、新check:actions、Build，再真实WebGL截图，上传90张动作图和握点/DIY/移动端/推拉三视图等额外图。产物含index.html、report.json和日志。Agent必须打开各动作图，不能把CI绿色当作美术通过。

`check:actions`覆盖9动作×3体型×61姿态（1647帧）：手部握点、脚底、蒙皮面、循环、单次终点、暂停/seek/跳帧事件、不逐帧重建Mesh、DIY不被改写。

进一步规范见 `GitHubActions截图验收规范.md`；实际修正记录见 `Phase4A使用与验收.md`。测试不证明任意姿势/服饰都没有自交；新动作、新服装仍需增加审查。
