# 动作系统架构 · Phase 4

## 状态与范围

2026-09-19 开始第一轮实现。本文是本轮执行契约，不代表代码或截图已经验收。

动作不按职业锁定。沿用 Recipe V4、固定 20 Bone ID、最多两个非零权重、+Z 向前、导航负责世界位移。运行时不重建人体 Mesh，不引入 FBX/GLB 动作库或布料物理。

## ActionDefinition

正式字段：稳定 id、显示标签、类别、duration（秒）、playback（loop / once / hold）、道具要求、归一化事件 phase、关键审查相位。

- loop：行走、抱箱行走、锄地。
- once：拾取、放下、拉弓、放箭、收弓；末帧保持，不能取模回起点。
- hold：持续瞄准；不重复生成事件。
- 事件按 (previousTime, currentTime] 派发，跨帧与跨循环不能漏发或重复。
- seek 只是无副作用的画面采样；暂停、拖动、倒回不能生成箭或执行游戏交互。
- 视觉道具状态由 action + phase 确定，不能只靠事件累加，所以直接拖到任意相位仍可正确审图。
- restart 明确重置播放游标；单次片段结束不自动无限循环。

## 动作与道具

动作使用既有骨骼和局部抓握偏移，不增加五指或工具人体骨骼。动作制作阶段可求解双段手臂 IK，最终保存骨骼局部四元数和 Hips 位移。IK 不成为远景居民运行前提。

弓、弓弦、箭、箱、锄头作为独立动作道具驱动；基础模型仍保留原来的装备数据与 Recipe 导出。显示动作道具时必须隐藏对应静态手持物，避免双份道具。道具变化不得重置头饰、衣物或背部配置。

兼容性只根据手部装备判断，不根据 preset 判断。弓手戴草帽也能射箭。不兼容时给出明确要求和仅调整双手的显式操作，不悄悄改配方。

射箭有 nock / raise / draw / hold / release / recover 阶段，弓弦中点与拉弦手保持一致，弓臂做确定性简化形变。箭离弦用于验证事件，不实现伤害、真实弹道或战斗 AI。

拾取/放下先使用固定低台面高度，避免把未实现的任意地面取物当成完成。箱子接触后附着，放下时解除。抱箱行走保留原地步态，双手不做普通摆臂。

锄地的双手握柄位置不同，具有抬起、下挥、触地、回收阶段。工具接触点要与事件一致，不能用屈膝片段换工具冒充。

## Unity 数据边界

可迁移的是 SkeletonDefinition、SkinBinding、MotionClip 局部轨道、ActionDefinition、事件与道具锚点。

Three.js AnimationMixer、WebGL Renderer 和浏览器调试对象不迁移。常用组合可以烘焙成全身片段，避免默认让大量居民实时运行多层 Animator/IK。

Unity MeshData / Burst、BlobAsset、GPU Bone Buffer / Animation Texture、Entities Graphics、LOD、万人性能仍未实现，不因网页动作通过而宣称完成。

## GitHub Actions 验收

仅使用 runner 内 Vite Preview + Playwright + Artifact，不恢复 Visual/Vercel 部署。

每个真正可播放的 Motion / Action 必须包含 Front / Side / Back / Cage 截图；循环片段包含 0/25/50/75%，交互片段增加接触、释放前后和末帧。检查默认身材与体型端点，并覆盖草帽弓手。

静态覆盖检查必须与实际截图产物核对；仅登记名称不算覆盖。自动检查还应覆盖：单次结束、保持瞄准、重复播放、取消、seek 无事件、跨帧事件、双手抓握误差、固定骨骼和步态方向。

Agent 连续完成：读文档 → 实现 → check:mesh / action checks / build → Actions 截图 → 下载并实际审图 → 修正并重跑 → 合入 main。不能只看绿色状态，也不能在未运行时写“已验收”。最终记录实际提交 SHA、run ID、检查数量、截图范围和局限。
