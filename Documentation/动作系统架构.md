# 动作系统架构 · Phase 4A

## 实现边界

2026-09-19：第一轮加入射箭和抱箱待机，并整合已提交的劳动动作基础。代码实现、自动检查和人工审图是三个独立状态；实际验收以 `Phase4A使用与验收.md` 和对应提交的 Actions 产物为准。

保留 Recipe V4、固定 20 Bone ID、每顶点最多两个非零权重、+Z 向前。所有人体与道具在运行时生成，不使用外部 FBX/GLB 人物或动作。正常播放不重建人体 Mesh，不运行逐帧人体 IK。导航世界位移由游戏侧负责。

## 模块与唯一入口

| 文件 | 职责 |
| --- | --- |
| actions/catalog.ts | 17 个可播放动作的稳定 ID、播放规则、道具占槽、阶段与事件 |
| actions/anchors.ts | 道具局部握点和接触点；标准身高 1.76m |
| actions/kinematics.ts | FK 与解析双段 IK，仅用于构建和离线检查 |
| actions/bake.ts | 劳动动作的人体、道具共同采样及烘焙 |
| actions/bow.ts | 射箭共同时间域、人体求解、弓/弦/箭节点轨道和运行时道具 |
| actions/dispatch.ts | 所有动作统一的 sampleWork / bakeWork / createWorkProps 入口 |
| actions/player.ts | 播放、定位、事件游标、道具可见性、握点调试 |
| actions/props.ts | 劳动道具运行时建模与释放 |

调用动作采样时使用 `dispatch.ts`，不要绕过它调用只处理劳动动作的 `bake.ts`。不要再以 `v3/actions.ts` 内的旧占位名作为完成清单；真正可播放的动作以 `catalog.ts` 为准。

## 当前动作

劳动 10 项：pick、place、carry_hold、carry_front、carry_shoulder、carry_back、push、pull、hoe、hammer。

射箭 7 项：bow_shot、bow_draw、bow_aim、bow_aim_high、bow_aim_low、bow_release、bow_cancel。它们包含完整流程、分段和瞄准姿势变体，不应宣传成七套完全独立的射箭流程。

原有待机、行走、慢跑、招手、屈膝、静态 A-Pose 仍由 `v3/rig.ts` 负责。

## 播放契约

ActionDefinition 使用 `duration`（秒）、`loop`（布尔值）和可选 `playback: 'hold'`。事件的 `phase` 为 0–1 归一化相位。

- 循环：负重行走、推拉、锄地、锤击、抱箱待机。
- 单次：拾起、放下、完整射箭、搭箭拉弓、放箭收势、取消。结束停在末帧，不取模回起点。
- 保持：三个瞄准变体。播放游标可以到末帧，但 `finished=false`，继续维持满弓，不再搭箭或释放。

语义事件按秒时间区间 `(previousTime,currentTime]` 处理；一次射箭只触发一次 `arrow_released`。暂停的零增量不触发事件。跳帧、跨循环和恰好落在事件边界均有回归检查。

seek 是无副作用画面采样：可以重现箭在空中的画面，但不执行游戏交互或创建新的逻辑箭。主动定位/重播重置调试事件计数；单纯暂停和结束不清空计数。

## 人体与道具

道具和人体共用时间轴、握点及坐标约定。双段 IK 在构建 Clip 时采样为局部骨骼四元数与 Hips 位移。运行时使用已烘焙轨道，不把实时全身 IK 变成几千居民的运行前提。

道具节点不是人体骨骼，不改变 Bone ID。显示工作道具时，`visibleRecipe` 克隆配方并临时隐藏占用的手/背槽，避免双份装备。原始 Recipe、导出、头饰和衣服不变，退出动作后恢复。这里是实验台的道具预览机制，不是游戏库存自动装备。

`mask: upper/full` 是动作内容元数据；当前常用组合烘焙成全身片段，没有实现通用运行时分层混合器。

## 射箭实现

完整 canonical 时间域：准备 → 简化取箭示意 → 搭箭 → 举弓 → 拉弓 → 瞄准 → 释放 → 收势。

`bow_draw` 末帧、`bow_aim`、`bow_release` 起点和 `bow_cancel` 起点共用同一满弓姿态，有 20 骨骼与拉弦点的接缝测试。取消通过单独无事件时间映射退弦，不倒放释放事件。

弓臂、两段弓弦、箭分别烘焙位置/旋转/缩放轨道。弦中点与拉弦手共用目标，释放后右手向后缓冲，不跟弦向前抽动。抬弓目标根据当前体型实际臂长限幅，不拉长骨骼或扩大测试容差。

箭离弦后使用固定释放锚点演示飞行，不跟随收弓。角色仍原地预览；这不是独立的世界投射物管理器，也没有伤害、命中或真实弹道。取箭只做示意，不声称手从背部箭袋中真实抽出箭。

高/低瞄准是约 ±0.2 弧度的独立姿势验证；当前完整射击和释放仍按标准方向演示。任意目标方向、随瞄准角发射和瞄准变体之间的平滑转换留待后续，不把它们当作已完成。

## 劳动与接缝

拾取/放下使用当前固定箱体与地面高度。抓稳后提起，落地后松手。`carry_hold` 复用拾取末帧，和放下起点一致。

抱箱行走、扛木、背柴、推拉是原地负重片段；手部持续对准道具握点。车轮当前按预览标定速度显示滚动，游戏接入时应改为实际行进距离。

锄地与锤击分别有工具轨迹、接触点和事件，不使用屈膝片段换道具冒充。

目前通过动作库选择不同片段，不包含跨动作物品生命周期状态机、任意中断姿势混合、场景寻路或资源生产结算。

## Unity 迁移边界

迁移内容：SkeletonDefinition、SkinBinding、局部骨骼轨道、事件相位、道具节点与抓握锚点。Three.js AnimationMixer 不迁移。

Unity MeshData/Burst、BlobAsset、Animation Texture/Bone Buffer、Entities Graphics、动画 LOD、万人性能验证均未实现。网页单角色 GPU 蒙皮不等于 Unity Crowd 已通过。

## 验收门槛

只使用 GitHub Actions runner 内 Vite Preview + Playwright + Artifact，不恢复 Visual/Vercel 部署。

保留基模/衣服/步态检查。17 动作 × 3 体型 × 61 相位检查真实骨骼矩阵、手部目标、弓弦、脚底、蒙皮有限性、事件、单次/循环/保持和网格复用。

`scripts/review-actions.ts` 独立矩阵和注册表双向核对，并验证实际文件存在。每动作 Front / Side / Back / Cage；按动作输出关键相位，射箭增加释放前、释放时、释放后。补充草帽混搭、体型端点、暂停/定位/取消/保持和移动端。

Agent 必须下载产物、实际查看每组姿势与阶段、修正并重跑。不允许只看绿色任务或截图数量便宣布美术验收完成。
