# 动作系统架构 · V3.5 / FBX ONLY

旧Phase4A程序动作已删除。旧射箭/劳动完整实现可查Git历史，不能恢复为隐藏对照或动画载入失败回退。

## 唯一正式路径

`动画参考/*.fbx → prepare-mixamo → MixamoMotionData → retargetMixamo → MixamoPlayer`

catalog.ts管理稳定ID、文件名、循环候选及地面策略；data.ts定义采样协议；retarget.ts在载入/体型改变时烘焙；player.ts负责时间游标、目标播放、源骨架对照、头向调试和释放。

rig只建立模型/骨架/蒙皮与静态绑定，不再创建程序KeyframeTrack。绑定姿态是检查状态而非Motion。默认打开jogging。

## 播放约定

唯一time游标决定源目标相位，正常播放推进；seek无业务副作用；暂停零增量不推进。非循环末帧保持不取模；循环需要首尾数值检查通过。加载失败提供重试或静态bind，保持配方和实验台。

更换片段复用几何，源异步代次隔离；换装/体型重建目标但保留相位。头部遵循实际源世界旋转差，不锁死朝向。没有实时全身IK、脚锁或通用混合器。

## 道具与业务边界

帽子、武器、箭袋是原DIY附件，跟随已有骨骼。外部动画未附带源道具/场景/第二个人。射箭的人体轨道已经导入，但精确握点、弓弦、箭、释放事件仍为空；不能移用已删除程序片段的时间。

以后按外部动画建立独立PropClip/EventTimeline，与人体共用语义时间，不给道具节点新增人体Bone ID。业务事件必须独立于渲染可见性/动画LOD，不可因角色不渲染而漏生产完成或放箭。当前没有这些任务/库存/伤害系统。
