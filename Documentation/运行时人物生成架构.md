# 运行时人物生成架构

## 1. 核心判断

正式角色不应被理解为一组 Mesh Asset。

角色应被理解为：

`Parameters + Recipe + Runtime Generator`

最终 Mesh 是运行时编译结果，可以被缓存，但不是内容制作的主要源数据。

## 2. 长期数据链

`ResidentAppearance`
-> `CharacterRecipe`
-> `Body / Garment / Accessory Generator`
-> `Topology + Vertex Attributes`
-> `Mesh Assembly`
-> `LOD`
-> `CharacterMeshKey`
-> `Mesh Cache`

颜色、皮肤色、布料色等尽量不进入几何 Hash。

## 3. Web 与 Unity 的对应关系

Web：

- Character Parameters：TypeScript；
- Blueprint：语义 Section / JointPatch / Ring；
- Generator：纯几何生成逻辑；
- Geometry：Three.js BufferGeometry；
- Preview：Three.js Scene。

Unity：

- Character Parameters：IComponentData / Blob；
- Blueprint / Recipe：BlobAsset；
- Generator：Burst Jobs；
- Geometry：MeshData；
- Runtime：Entities / Renderer / Cache。

两端保持语义一致，不要求 API 一致。

## 4. Phase 0

Sphere / Cylinder 只用于证明运行时生成与单 Mesh 数据流，已经退出正式生成路径。

## 5. Phase 1：Ring Topology

基础链：

`BodyParameters -> HumanTopologyBlueprint -> BodySection -> SectionRing -> BufferGeometry`

稳定概念：

- `BodySection`：连续身体主干；
- `SectionRing`：沿中心线的椭圆截面；
- `BodyRegion`：稳定区域语义；
- 固定 Ring 顺序；
- 参数只改变位置与截面，不改变语义顺序。

## 6. Phase 1.5：JointPatch v1

Blueprint v2 新增：

`JointPatch`

当前只实现 ShoulderPatch。

目标：

- 不让 Arm Root 继续以封口圆柱直接贴在 Torso 外；
- 给 Chest → Deltoid → Arm Root 建立独立过渡语义；
- 为以后真正共享边界留出明确层次。

当前 ShoulderPatch 是四段 Ring：

`ChestSocket -> DeltoidInner -> DeltoidOuter -> ArmRoot`

Arm Section 从同一 ArmRoot 参数继续向 Elbow / Wrist / Hand 生成，且 `capStart=false`。

当前限制：

- ChestSocket 仍与 Torso 表面相交；
- ShoulderPatch / ArmRoot 目前重复顶点；
- Torso 尚未开孔；
- 尚未无重叠焊接。

因此 v1 是“建立 JointPatch 数据模型 + 改善轮廓”，不是最终分叉拓扑。

## 7. Ring Mesh 编译

`ringGeometry.ts` 负责：

- Ring Center；
- 相邻 Ring 推导中心线 Tangent；
- 局部 Right / Forward Frame。

`buildTopologyGeometry.ts` 负责：

1. 遍历 BodySection；
2. 遍历 JointPatch；
3. 写入 Position；
4. 写入 `bodyRegion`；
5. 连接相邻 Ring Index；
6. 按需生成 Cap；
7. 计算 Normal / Bounds；
8. 输出单 BufferGeometry。

## 8. Debug Review

网页 Debug View 是拓扑开发工具，不是最终游戏 UI。

当前显示：

- Shaded；
- Wireframe；
- Wire Overlay；
- Body Region Colors；
- Ring Guides；
- Grid / Axis；
- Perspective / Orthographic；
- 3/4 / Front / Back / Left / Right / Top。

Review 的核心用途：

- 正交前视检查左右对称和宽度关系；
- 正交侧视检查 Chest / Pelvis / Head 深度；
- Wire Overlay 看三角面走向；
- Ring Guides 看截面跳变；
- Regions 检查 JointPatch 语义边界。

## 9. Shoulder Shared Boundary 下一目标

下一版不能继续靠相交。

目标数据关系：

`Torso Shoulder Opening Boundary`
-> `ShoulderPatch Shared Start`
-> `ShoulderPatch Shared End`
-> `ArmRoot Shared Boundary`

需要：

- 可命名 Boundary；
- 可复用顶点索引；
- 支持 Section 局部跳过面片，形成 Opening；
- Patch Builder 引用已有 Boundary；
- Normal 在共享顶点上连续。

完成后，HipPatch 才允许复用这套通用机制。

## 10. 服装方向

服装不保存最终 Mesh。

长期使用 GarmentRecipe，例如：

- 覆盖 Region；
- 衣长；
- 宽松度；
- 袖长；
- 袖宽；
- 领型；
- 下摆；
- Material Role；
- Body Hide Region。

## 11. 大规模运行约束

长期策略：

- 几何参数量化；
- CharacterMeshKey；
- Mesh Cache；
- 颜色不进入几何 Hash；
- LOD 按不同 Ring 采样密度直接生成；
- 近远景骨骼复杂度分级。

## 12. 当前目录职责

`src/character/types.ts`
人物参数。

`src/character/topology.ts`
BodySection / JointPatch / Region 等拓扑协议。

`src/character/ringGeometry.ts`
Ring Frame 数学。

`src/character/createHumanTopologyBlueprint.ts`
参数解析成 Blueprint。

`src/character/buildTopologyGeometry.ts`
Blueprint 编译成顶点与索引。

`src/character/generateHumanoidGeometry.ts`
薄编排入口。

`src/scene/createTopologyDebug.ts`
只负责 Web Debug 可视化。

`src/scene/CharacterViewport.tsx`
相机、投影、Renderer 和 Debug 显示。

`src/App.tsx`
实验 UI，不包含核心几何算法。
