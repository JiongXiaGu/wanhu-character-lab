# 运行时人物生成架构

## 1. 核心判断

正式角色不应被理解为一组 Mesh Asset。

角色应被理解为：

`Parameters + Recipe + Runtime Generator`

最终 Mesh 是运行时编译结果，可以被缓存，但不是内容制作的主要源数据。

## 2. 长期数据链

`ResidentAppearance`
-> `CharacterRecipe`
-> `Body / Garment / Accessory Generator`
-> `Topology + Vertex Attributes`
-> `Mesh Assembly`
-> `LOD`
-> `CharacterMeshKey`
-> `Mesh Cache`

颜色、皮肤色、布料色等尽量不进入几何 Hash。

## 3. Web 与 Unity 的对应关系

Web：

- Character Parameters：TypeScript 数据；
- Generator：纯生成逻辑；
- Geometry：Three.js BufferGeometry；
- Preview：Three.js Scene。

Unity：

- Character Parameters：IComponentData / Blob；
- Generator：Burst Jobs；
- Geometry：MeshData；
- Runtime：Entities / Renderer / Cache。

两端保持“语义一致”，不要求 API 一致。

## 4. Phase 0 已完成

Phase 0 用 Sphere / Cylinder 等运行时基础几何验证了：

- 参数可以实时驱动人体变化；
- 不需要加载 FBX / GLB；
- 多个身体部位可以在运行时合并成一个 Mesh；
- UI、生成核心与场景渲染可以保持分离。

该实现仅作为架构探针，现已退出正式生成路径。

## 5. Phase 1 当前实现

当前生成链已经切换为：

`BodyParameters -> HumanTopologyBlueprint -> BodySection -> Ring -> BufferGeometry`

核心类型：

- `HumanTopologyBlueprint`：一次人体拓扑编译的语义蓝图；
- `BodySection`：一个连续的身体区域；
- `SectionRing`：该区域沿中心线的一个椭圆截面；
- `BodyRegion`：稳定的身体区域语义；
- `TopologyStats`：用于实验页观察生成规模。

当前 Blueprint v1 包含：

- Torso；
- Head；
- Left / Right Arm；
- Left / Right Leg；
- Left / Right Foot。

每个 Section 使用固定 Ring 顺序和固定径向采样数。参数变化只改变 Ring 的中心、Width / Depth，不改变语义顺序。

## 6. Ring Mesh 编译规则

`buildTopologyGeometry.ts` 不调用 Three.js Sphere / Cylinder 等成品几何。

它直接：

1. 读取 Section 中的 Ring；
2. 根据相邻 Ring 中心计算局部切线；
3. 建立截面局部坐标系；
4. 写入每个 Ring 的顶点；
5. 按固定顺序连接相邻 Ring；
6. 写入 Index；
7. 写入 `bodyRegion` 顶点属性；
8. 最终得到单个 `BufferGeometry`。

当前 UV 尚未进入正式协议。纹理接缝方案将在服装和材质阶段单独设计，避免现在为临时 UV 固化错误拓扑。

## 7. 当前已知限制

Phase 1 v1 有意保留以下限制：

- Shoulder / Hip 等分支仍然通过重叠连接；
- Arm / Leg 与 Torso 尚未共享边界顶点；
- 尚未实现 `JointPatch`；
- 头颈连接尚未焊接；
- 手部仍是极简 Ring 轮廓；
- 没有 Skeleton；
- 没有 Skin Weight；
- 没有 UV；
- 没有服装；
- 没有 LOD。

这些限制不通过继续添加 primitive 修补。

## 8. 下一阶段：JointPatch

下一步优先解决：

- ShoulderPatch；
- HipPatch；
- NeckPatch；
- Wrist / Ankle 的必要过渡。

目标不是立刻雕出高质量人体，而是让分支区域开始共享稳定边界，为后续：

- Skin Weight；
- Body Region Hide；
- Garment Surface；
- LOD Sampling；

建立可复用拓扑语义。

## 9. 服装方向

服装不保存为最终 Mesh。

长期使用 GarmentRecipe，例如：

- 覆盖 Region；
- 衣长；
- 宽松度；
- 袖长；
- 袖宽；
- 领型；
- 下摆；
- Material Role；
- Body Hide Region。

生成器根据当前身体表面生成服装几何。

## 10. 大规模运行约束

不要默认“一居民一独立永久 Mesh”。

长期策略：

- 几何参数量化；
- 生成 CharacterMeshKey；
- Mesh Cache；
- 相同几何不同颜色共享 Mesh；
- LOD 直接按不同采样密度生成，不先生成高模再做运行时减面；
- 近景与远景骨骼复杂度分级。

## 11. 当前目录职责

`src/character/types.ts`

人物可调参数。

`src/character/topology.ts`

稳定的拓扑语义类型。

`src/character/createHumanTopologyBlueprint.ts`

把人物参数解析为语义 Section / Ring。

`src/character/buildTopologyGeometry.ts`

把 Blueprint 编译为顶点与索引。

`src/character/generateHumanoidGeometry.ts`

保持为最薄的编排入口。

`src/scene/`

负责相机、灯光、Orbit、Renderer 和 Debug 展示，不拥有生成算法。

`src/App.tsx`

负责实验参数、线框开关和统计展示，不包含具体人体几何算法。
