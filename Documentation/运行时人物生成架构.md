# 运行时人物生成架构 · V3.5

## 生成链

`Preset → Recipe V4 Slots → makeBody → makeCharacter/shapePoint → CharacterData → makeActor → SkinnedMesh/Skeleton`

Preset只是一键填槽位，不参与最终职业分支。types/cage/body/outfit不依赖Renderer；rig是Three.js验证适配层，不生成动画。FBX载入后由独立MixamoPlayer播放；静态绑定调用resetBindPose，不能有隐式呼吸/走路。

头颈、躯干、双臂、裆和双腿是连续封闭表面。肩/髋固定拓扑连接，不用相交块、不做最近点焊接。逻辑Cage与渲染顶点分开；硬法线/颜色可拆点但权重不变。四边面固定三角化。

## 骨架与蒙皮

固定Bone IDs：0Root、1Hips、2Spine、3Chest、4Neck、5Head、6RightClavicle、7RightUpperArm、8RightForearm、9RightHand、10LeftClavicle、11LeftUpperArm、12LeftForearm、13LeftHand、14RightThigh、15RightShin、16RightFoot、17LeftThigh、18LeftShin、19LeftFoot。职业/服装/身材不得改变ID和父关系。

SkinBinding=[BoneA,BoneB,WeightA]，WeightB=1-WeightA。最多两非零影响，普通区尽量单骨，肩肘髋膝颈双骨。Web用标准四通道，但后两通道为0。

主体GPU蒙皮，不逐帧重建Mesh。CPU只用于结构线Debug和数值参考，不作为Crowd方案。人体绑定位置与实际体型有关，不能无验证共享最终骨矩阵。

## FBX路径

`FBX → 真实inverse-bind/源世界旋转差 → 当前体型校准/局部轨道烘焙 → 唯一FBX播放器`

+X人物右、+Y上、+Z前。导航接管世界位移，保留骨盆侧摆/俯仰/高度。头部不以HeadTop_End推断脸向，见男性FBX校正.md。

切换FBX只释放播放器/轨道，不重建几何；更换Recipe才重建模型并保留片段相位。异步generation防止旧加载结果覆盖新选择。源缓存有限且与体型/衣服无关。

## DIY与服装

Recipe V4：preset、headwear/top/bottom/shoes/back/leftHand/rightHand、height/build/palette。修改槽位变custom，不偷偷重置其余槽位。旧V3参数只在cleanRecipe迁移。

短衣、裤子、绑腿和轻甲通过覆盖表面替换，不同时保留完整裸体+衣物重合面。领口/腰带/五官/头发/装备附加面。衣物共享Skeleton；帽子Head、工具Hand、箭袋Chest/Back。服装无独立Animator。

## 缓存与迁移

几何键：BodyTopologyVersion、BodyProportionKey、量化height/build、SlotRecipe、LOD；当前顶点颜色影响几何，不能未经重构就排除配色。

动画键：源SHA、retargetVersion、SkeletonVersion、BodyProportionKey/height/build、片段ID。单居民目标只持Transform、MeshKey、外观参数和ClipId/Phase/Speed，不持独占整份网格/动画库。

迁移数据而非Three.js类。先Unity单人骨架/蒙皮逐帧对照，再Blob/GPU骨缓存/实例化/LOD；这些Unity实现均未完成。
