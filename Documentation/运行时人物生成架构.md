# 运行时人物生成架构

## 1. 当前核心方向

正式角色不是一组预制 Mesh Asset，而是：

`Parameters + Recipe + Runtime Generator`

当前人体采用：

`Segmented Low-Poly Humanoid`

核心原则：

- 极低面数；
- 固定、可预测拓扑；
- 身体部件逻辑分段；
- 关节允许少量互相穿插；
- 优先刚性或有限蒙皮；
- 运行时最终仍编译为一个 Mesh；
- 近景主要靠轮廓、材质、服装和头发提升观感，而不是堆裸体人体环线。

## 2. 已停止的路线

Phase 1 / 1.5 曾验证：

- Ring Topology；
- JointPatch；
- Shoulder Opening；
- Shared Boundary；
- 连续 Torso → Arm 拓扑。

技术上可以工作，但对于《万户天工》的大规模城市居民，复杂度与收益不匹配。

因此不再继续：

- HipPatch；
- NeckPatch Welding；
- 连续裸体 Mesh；
- 复杂 Smooth Skinning 作为默认方案。

旧实现已经退出正式运行链，并在 Low-Poly 路线确认后删除，避免后续误接回旧架构。

## 3. 当前生成链

```text
BodyParameters
→ resolveHumanLandmarks
→ createLowPolyHumanoidBlueprint
→ LowPolyPart[]
→ PrismSection[]
→ buildLowPolyGeometry
→ validateLowPolyGeometry
→ BufferGeometry
```

当前人体由 16 个逻辑部件组成：

- Head；
- Neck；
- Torso；
- Pelvis；
- Left / Right UpperArm；
- Left / Right LowerArm；
- Left / Right Hand；
- Left / Right UpperLeg；
- Left / Right LowerLeg；
- Left / Right Foot。

## 4. 固定截面

只允许三种基础截面：

- `box4`
- `hex6`
- `oct8`

推荐：

- Hand / Foot / Neck：box4；
- Head：oct8；
- Arms / Legs：hex6；
- Torso / Pelvis：oct8。

这里借鉴的是 Minecraft 式分段角色的工程思想，而不是方块外观。

## 5. 参考成熟系统后的架构取舍

### MakeHuman / MPFB

MakeHuman 的重要经验不是“高模人体”，而是：

- 基础拓扑语义稳定；
- 参数变化与拓扑结构分离；
- Rig 定义与 Mesh 数据分离；
- 骨骼位置可以根据稳定的身体语义重新拟合。

本项目对应采用：

- 稳定 `BodyPartId`；
- 稳定部件顺序；
- 身材参数只改变截面位置与尺寸；
- 下一阶段 RigDefinition 独立于 Mesh Compiler；
- 骨骼 Pivot 从身体语义位置计算，不硬绑 Web 顶点序号。

### UMA

UMA 的重要经验是：

- Recipe 和最终 Mesh 分离；
- Character Build 是独立流程；
- Mesh Combine 是明确阶段；
- LOD 不应该和人物内容定义混在一起。

本项目对应采用：

```text
CharacterRecipe
→ Geometry Blueprint
→ Mesh Compiler
→ Validation
→ Cache
→ Renderer
```

但不会照搬 UMA 的 Slot Mesh 资产体系；人体和服装仍以程序规则生成。

## 6. Human Landmarks 与轮廓

当前通过 `resolveHumanLandmarks.ts` 统一定义：

- ankle；
- knee；
- hip；
- lower abdomen；
- waist；
- chest；
- shoulder；
- neck base；
- head bottom / top。

Mesh、后续 Rig、服装都应引用这套语义位置，而不是各自维护一套比例常数。

`PrismSection` 支持独立的 positive / negative depth，用于低面数下分别控制前胸/后背、腹部/臀部等前后轮廓。核心 Torso / Pelvis / Head 保持直中心线，避免非共面四边面在三角化后产生无意义的对角折面。

## 7. 关节

关节默认允许相邻部件重叠约 5%～15%。

例如：

```text
Torso
  overlaps
UpperArm
```

以及：

```text
UpperLeg
  overlaps
LowerLeg
```

这样可以：

- 保持布线规则；
- 大幅减少三角面；
- 避免复杂共享边界；
- 简化骨骼动画；
- 让 LOD 可以直接替换截面配置。

## 8. 三角面绕序

Three.js / WebGL 的正反面由 Triangle Winding 决定。

当前规范：

- 所有外表面必须以外侧 Counter-Clockwise 生成；
- 不通过 `DoubleSide` 掩盖绕序 Bug；
- Side Wall 与 Start / End Cap 分别有明确绕序规则；
- CI 必须检测 inward triangle。

之前实体显示异常就是由整体绕序反向造成，现已修正。

## 9. Mesh Validation

`validateLowPolyGeometry.ts` 检查：

- 非有限数值顶点；
- Degenerate Triangle；
- Inward Triangle；
- Triangle 跨 BodyPart；
- Triangle Budget 超限。

CI 使用至少四组体型参数：

- Default；
- Tall / Thin；
- Short / Heavy；
- Broad / Average。

任何一组失败都阻止 Build 通过。

当前基准：

```text
306 tris
228 verts
inward = 0
degenerate = 0
mixed = 0
overBudget = 0
```

## 10. 顶点与 Index 数据布局

Web 当前保持紧凑语义：

- Position：Float32 × 3；
- Normal：Three.js 生成；
- bodyPart：UInt8；
- boneIndex：UInt8；
- Index：UInt16。

基础人物被强制限制在 UInt16 Index 范围。

未来 Unity 对应：

- Position：float3；
- Normal：可解析生成或压缩；
- Part / Bone / Material Role：byte / ushort；
- Index：UInt16；
- 通过 MeshData + Burst 批量写入。

颜色、皮肤色、布料颜色等不进入 Geometry Key。

## 11. 面数预算

当前裸体基础人物：

- 硬上限：500 tris；
- 当前默认：306 tris；
- 当前默认：228 vertices。

后续方向：

- LOD0：约 300～600 tris（含基础衣物后重新定）；
- LOD1：约 150～300 tris；
- LOD2：约 60～150 tris；
- 极远：Impostor / Billboard。

最终预算以 Unity 实机 Profile 为准。

## 12. 服装方向

服装继续运行时生成，但优先沿用低模分段思想。

例如：

```text
Torso Prism
→ outward scale / silhouette rule
→ Shirt Shell
```

裤子：

```text
UpperLeg / LowerLeg
→ outward shell
→ Pants
```

长袍、裙装、宽袖等使用独立低模轮廓 Recipe。

不要回到：

`每件衣服一个 FBX / GLB`

## 13. Debug Review

网页保留：

- Shaded；
- Wireframe；
- Wire Overlay；
- Part Colors；
- Part Guides；
- Grid / Axis；
- Perspective / Orthographic；
- Front / Back / Left / Right / Top / 3/4。

自动 Visual Review 固定生成：

1. 3/4 Perspective Overlay；
2. Front Orthographic Overlay；
3. Right Orthographic Overlay；
4. Top Orthographic Overlay；
5. Front Orthographic Wireframe。

其中 Front / Right / Top 是人物形体修改的硬门槛；Build 与 Mesh Validation 通过不能替代三视图人工 Review。

重要模型修改必须同时满足：

- Mesh Validation；
- Build；
- Visual Review。
