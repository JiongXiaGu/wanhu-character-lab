# 运行时人物生成架构 · V3

## 数据与实现

Recipe 保存职业、身高、体格、头饰、装备和颜色组；cleanRecipe 限制合法范围。生成链为：

```text
Recipe
→ makeBody：固定三维 cage，人体共享顶点
→ makeCharacter：BodyDerived.Replace 和额外装备
→ shapePoint：人体、衣物和骨架共用身材变换
→ CharacterData
→ makeActor：渲染拆点、法线、颜色、权重
→ SkinnedMesh + Skeleton + AnimationMixer
```

头、颈、躯干、双臂、裆部、双腿共享连续人体表面。肩和髋使用固定连接，不做运行时最近点焊接。主体四边面最终固定三角化。逻辑 cage 与渲染顶点不同：每个 face 的颜色/硬法线可拆点，拆点保留相同位置和权重。

## 骨骼与动作

20 个稳定骨骼语义：Root、Hips、Spine、Chest、Neck、Head、左右锁骨/上臂/前臂/手、左右大腿/小腿/脚。

每顶点最多两个非零权重；在 Three.js 中仍用标准四通道属性，剩余通道为零。不能因此宣称 GPU 只执行两个矩阵变换，Unity 的优化渲染路径待迁移时验证。

动作在构建时生成循环 AnimationClip，运行时由 AnimationMixer 驱动骨骼，不重建模型。待机、行走、慢跑、招手、屈膝和静态 A-Pose 已接入；行走/慢跑是原地演示，不包含游戏导航位移。

结构线框仅在调试模式中根据同一蒙皮矩阵更新，非默认角色 CPU 变形路径。

## 服装与装备

目前短衣、裤子、绑腿和轻甲轮廓采用覆盖区域表面替换；不再在同一位置保留一份裸体。领口、腰带、五官、头发和装备是附加面。所有顶点仍使用同一骨架。

替換三角形统计表示覆盖区的可见表面被替换，不是通用 Body Hide mask 已完成。通用宽袖、长袍、护肩和多层盔甲应另行增加 Recipe，不在本轮宣称已做完。

## 验证和限制

自动检测包括人体闭合连通、Euler 特征、镜像、真实锚点边、索引范围、零面积面、封闭装备方向、骨骼编号、权重和、Bind Pose 一致性、循环首尾一致性、姿态采样非有限数和塌面。

这些检查不证明所有姿势没有自交或穿模。正/侧/背、3/4 和动作截图仍必须实际查看。

目前每个角色采用一个 SkinnedMesh / 一个材质；阴影、调试网格、线框等额外 pass 不能算作一个总 draw call。GPU 拆点数在界面单列。

## Unity 迁移

types/cage/body/outfit 的数据和计算不依赖 Three.js；rig 是 Web 适配层。迁移时应重新实现 MeshData、骨骼/动画与缓存调度，并针对实际居民数量与目标硬件测量；当前无 Unity 实测结果。
