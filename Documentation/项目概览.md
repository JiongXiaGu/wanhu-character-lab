# Wanhu Character Lab 项目概览

Wanhu Character Lab 是《万户天工》的程序化人物生成实验项目。

## 为什么单独做网页实验

《万户天工》需要大量城市居民，同时又允许玩家在较近距离观察人物。

传统“身体 Mesh + 上衣 Mesh + 裤子 Mesh + 鞋 Mesh”的资产式换装会带来：

- 大量独立 Mesh 资产；
- 多 Renderer；
- 身材与服装适配成本；
- 穿模；
- LOD 资产膨胀；
- 大规模居民的缓存与复用困难。

因此本项目优先验证另一条路线：

`Character Recipe -> Runtime Generator -> Final Mesh`

角色几何由参数和规则生成，最终 Unity 运行时再通过适合大规模场景的方式构建与缓存。

## Web 与 Unity 的职责

Web：

- 快速调参数；
- 快速观察人体比例和服装轮廓；
- 验证生成算法；
- 验证 Recipe；
- 验证数据协议；
- 提供可视化 Debug。

Unity：

- 正式大规模运行；
- Burst / Jobs；
- MeshData；
- ECS 生命周期；
- LOD 与距离调度；
- Mesh Cache；
- 动画和蒙皮；
- 最终材质与渲染。

Web 不是 Unity Runtime 的替代品。

## 目标数据流

`CharacterRecipe -> CharacterGenerator -> MeshDescription -> Renderer`

未来 Unity 对应：

`ResidentAppearance -> CharacterMeshKey -> MeshBuildRequest -> Burst Jobs -> MeshData -> Mesh Cache`

## Phase 0

当前只验证最小闭环：

- React 参数面板；
- Three.js 预览；
- 程序化生成简化人体；
- 单 Mesh；
- 无外部人物 Mesh 资产；
- Vercel 可部署。

现阶段的人体由多个运行时基础几何生成后合并，只用于验证架构。

## 后续阶段

Phase 1：HumanTopologyBlueprint / Ring / Section。

Phase 2：统一 Skeleton 语义与运行时 Skin Weight。

Phase 3：Body Region 与 Garment Recipe。

Phase 4：服装参数化轮廓、身体遮蔽、材质语义。

Phase 5：LOD Generator 与 CharacterMeshKey Cache。

Phase 6：Unity 版本验证，并开始以 Unity 性能结果反向约束 Web 实验。

## 非目标

本项目暂不追求：

- 成为通用 Avatar SaaS；
- Web 端生产级多人系统；
- Web 端保存最终人物 Mesh 作为游戏资产；
- 通过大量现成角色模型堆出内容量；
- 在早期就解决所有古代服饰类型。
