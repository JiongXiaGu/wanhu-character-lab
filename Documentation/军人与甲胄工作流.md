## 目标与边界

军人视觉的第一轴是甲装等级 `light / medium / heavy`，分别表达轻短灵活、标准正规军甲装、宽厚沉稳的甲胄体量。第二轴是驻地 `palace / frontier / city`，主要拥有 palette 和头盔风格。第三轴只有 `soldier / captain`，身份差异只来自 headwear variant。

重甲是一套中性、可染色、可供三种驻地复用的资产，不制作皇宫重甲、边疆重甲、城市重甲三份近似几何。大轮廓、体量和色块优先于胸前小纹样；不绑定唯一朝代，不做魔幻巨肩。

Web 只验证外观、蒙皮、动作适配和经营视角识别，不实现战斗数值、征兵、军籍、军饷、编制、AI、寻路、阵型或城防玩法。正式玩法协议留给 Unity。

## 数据所有权与不变量

`src/soldier/` 只拥有外观试衣、甲装分类、驻地配色和头盔选择，不建立第二套人物生成器。作者几何仍位于 `src/character/wardrobe/assets/military/`，沿原装配、封口和染色链路工作。

Recipe 保持 V5 精确六字段：`version / bodyType / slots / dyes / hairStyle / hairColor`；slots 保持 `headwear / top / bottom / shoes / back / leftHand / rightHand` 七槽位。不增加 `serviceStyle / armorClass / soldierIdentity / profession / role / rank` 或额外装备槽。甲装等级由实际 top + bottom 推导，混搭不能被强行识别成完整等级；身份由真实 headwear 推导，不单独持久化。

固定男女基模、20骨、最多双权重、inverse bind、Actor 生命周期、Renderer 数量、Mixamo/MediaPipe/GLB 动作链路、保存与染色协议保持。不增加肩甲骨、甲裙骨、动态肩甲、实时布料或新人物页面。

## S6 分阶段执行

每轮只推进一个阶段，通常控制为 2–4 个代码/检查文件及必要工作流说明。遇到另一层的问题先记录阻塞，不顺手改另一层。提交前检查本轮 diff；既有 PR 的累计差异必须与本轮增量分开说明。任何阶段都不能通过删检查、降采样、放宽容差或伪造截图换取通过。

### S6-1：作者几何与快速数值检查

范围是 `heavy-top.ts`、`heavy-skirt.ts` 及对应作者检查。已有重甲工厂不推倒重做，先验证其真实产物；需要修正时只修改重甲几何/权重与真实故障断言。中甲、轻甲、头盔、UI、驻地逻辑及动作系统冻结。

上甲应有更宽厚的外肩、更深的胸腹截面和明确护臂；内腋保留活动净空，不靠整体等比放大中甲。下装应有更强腰甲、外展侧甲和厚前后摆，不靠继续拉长裙摆。保持腰起、正背跨中线、两个真实裤腿出口和单一闭合壳，不恢复六块大腿外挂板或外露黑短裤。

当前候选封口后作者预算为上甲 432 tris / 218 逻辑顶点，下装 348 tris / 176 逻辑顶点，共 780 tris。预算不含复用头盔、军靴和长枪；不得与整个人物渲染面数混用。预算不是已获用户美术认可的声明。

独立入口：

```sh
npx tsx scripts/check-soldier-heavy-authoring.ts
```

入口只执行作者资产检查，不准备外部动作、不启动浏览器、不生成截图。验证男女×三驻地 palette 下的真实上/下装、闭合连通、非流形、有限坐标、20骨内的合法双权重、精确预算、轮廓差异、输入配方不被修改，以及同一性别下换 palette 不改变几何/拓扑/权重。复用并执行删面、反面、重复面、NaN、错误骨骼、错误侧腿及破坏轮廓等故障注入。
