# 军人与甲胄工作流

当前 S1 皇宫、S2 边疆、S3 城市均有独立作者资产和原工坊入口，分别见[皇宫禁卫与长枪](皇宫禁卫与长枪.md)、[边疆戍卒与长枪](边疆戍卒与长枪.md)和[城市守军与长枪](城市守军与长枪.md)。正式检查、实际看图和用户美术认可按对应 PR 分开记录；未完成验收不合并，S4 普通士兵／队长的头盔识别见[普通士兵与队长](普通士兵与队长.md)。

## 目标与边界

《万户天工》的军人外观采用泛中国古代军伍语言，以宋至明时期常见的札甲、布面甲、甲裙、护肩、盔缨等结构作为视觉参考，不绑定唯一朝代。第一层分类改为甲装等级：当前 `light` / `medium`，`heavy` 留到下一阶段。皇宫、边疆、城市降为驻地视觉副轴，主要拥有 palette 与头盔语义；兵种和普通/队长仍是独立维度。不能再把“驻地 = 一整套独占甲胄”。

Web 项目继续只验证人物外观、蒙皮、动作与中远景识别，不实现战斗数值、征兵、编制、AI、寻路、阵型、武器伤害或城防玩法。正式士兵身份、兵种、军阶与编制留给 Unity 运行时。

## 数据所有权与不变量

`src/soldier/contract.ts` 只拥有军人风格分类、计划资产 ID、首批制作顺序和基础配色，不建立第二套人物生成器。真实甲胄仍进入现有 `src/character/wardrobe/` 资产、装配、封口与染色链路；头盔、武器和背具继续使用既有对应槽位与作者路径。

人物 Recipe 保持 V5 精确六字段和七槽位：

- `headwear`
- `top`
- `bottom`
- `shoes`
- `back`
- `leftHand`
- `rightHand`

不得新增 `soldierStyle`、`profession`、`role`、`rank`、`armorSlot` 等字段。军装仍是一组普通外观资产，玩法身份不由外观配方决定。

人物继续使用现有 20 骨、最多双权重和同一套动作重定向；不增加盔甲骨、肩甲骨、甲裙骨或军人 Animator。旧 `guard_light_armor`、`archer_tunic`、`guard_pants`、`archer_pants`、`loose_trousers`、`boots` 已退役，不得为了军人功能恢复兼容。

## 当前甲装等级与驻地副轴

| 甲装等级 | 当前轮廓 | 正式衣甲资产 | 当前用途 |
|---|---|---|---|
| 轻甲 `light` | 短上甲、束腿军裤、整体轻便 | 城市现有 `city_guard_brigandine` + `city_guard_trousers` | 当前轻甲原型 |
| 中甲 `medium` | 完整札甲、长甲裙与裤管 | `medium_armor` + `medium_armor_skirt` | 皇宫、边疆共享 |
| 重甲 `heavy` | 下一阶段另做明显更重的体量 | 尚无 | 不注册占位 |

驻地不再负责复制整套近似甲胄。皇宫与边疆使用相同中甲几何：皇宫为绛红/黑铁/暗铜并配宫卫盔，边疆为深靛灰/旧铁/暗赤并配护颈盔。城市当前使用轻甲和城市低檐盔。经营视角的第一读层是轻/中/未来重甲轮廓，第二读层才是驻地大色块和头盔。

## 甲胄作者规则

上甲作为一个完整 `top` 资产制作胸甲、护肩、护臂和内衬，不拆成新的自由槽位。肩甲允许 Chest 与对应 UpperArm 的有限双权重，使抬臂时保持贴肩，但不能新增肩甲骨或逐帧碰撞。

甲裙作为一个完整 `bottom` 资产，首先满足从腰部垂下的整体军装轮廓。用户已否定S1首稿的六块大腿外挂板，宫卫改为前后跨中线的短裙甲与两个真实裤腿出口，具体作者规则集中在《皇宫禁卫与长枪》。可按风格使用分片或整体裙摆，不能把固定“六片”当作正确美术的保证；不得为分片独立而牺牲前摆与腰部衔接。权重来自现有Hips/Thigh，单点最多双权重；不增加裙骨，不把居民连续裙的压力边界或封底接触豁免移植给军装。

头盔保持闭合、不透明、Head 刚性权重；只有经过明确建模的帽底可以隐藏头发，不能靠大范围穿头豁免。军靴仍走鞋槽和现有脚踝接口。

建议单套新增几何控制在约 700–1100 tris：头盔 100–180、上甲 280–420、下甲 180–280、军靴 60–100、单件武器 60–180。甲片节奏优先通过低模折面、分区和少量结构条带表达，不逐片堆叠几十个高成本小壳。

## 制作阶段

### S0：军人工作流与契约

S0建项时只建立三类风格、计划 ID、作者边界、`check:soldier` 与 Targeted 作用域。不新增可见军装、不改人物 UI、不升级 Recipe。

### S1：皇宫禁卫第一套

先完成一名“皇宫禁卫 · 长枪”：

- `palace_guard_helmet`
- `palace_guard_armor`
- `palace_guard_skirt`
- `military_boots`
- `military_spear`

这一套负责验证红缨高盔、宽肩黑甲、腰起整体短甲裙、军靴、长枪、男女固定基模和现有 20 骨动作。只有真实资产与检查通过后再加入合法 ID、UI 和视觉审查入口。

### S2：边疆戍卒

边军三件独立资产复用原军靴/长枪和试衣入口，重点验证厚胸、护颈、长甲裙及靛灰/旧铁轮廓。现在已有资产、男女轮廓断言与原完整动作检查接入；只在正式检查和真实 WebGL 审图完成后合并，不把作者文件存在或旧宫卫检查通过当作 S2 完成。

### S3：城市守军

城市采用独立低檐盔、窄肩浅胸的布面短甲、外扩腰带和束腿军裤，复用军靴与长枪，不制作第三套甲裙。三件资产走原七槽位和试衣入口；实际轮廓断言、原完整动作/穿插与三套同机位对比共同验收，不能用作者文件存在代替完成。

### S4：普通士兵／队长，两态头盔识别

只增加 palace_captain_helmet、frontier_captain_helmet、city_captain_helmet 三个独立头饰资产。身份只支持 soldier／captain，不增加队长衣裤、腰扣、鞋靴或武器。原驻地套装复用，切身份只替换 headwear；试衣状态由头盔反推，Recipe 不新增字段。原 SoldierRoleId 继续表示规划兵种，不能用它冒充身份。

设计服务于模拟经营高空视角、大量单位的低成本识别和资产数量控制。用户已否定首版宽短缨、肥厚后拖与低横冠，当前队长只采用细高、居中、收尖的竖饰。识别通过实际经营俯视与正侧背检查，不再以横向面积越大越好代替美术判断；不能只改颜色或增加正面小徽章。普通头盔、衣甲和原动作保持，详细作者职责及入口见《普通士兵与队长》。

### S5：甲装等级收敛

S5 删除边军厚甲和皇宫短甲裙，保留宫卫上甲几何与边军长甲裙几何并转为共享中甲 `medium_armor` / `medium_armor_skirt`。皇宫/边疆不再靠胸厚、肩宽、裙长制造两套近似中甲；它们只保留头盔、队长顶饰和 palette 差异。城市现有短甲/军裤记为当前轻甲。

下一阶段再制作 `heavy` 重甲，必须产生明显更重的中远景轮廓，不能把中甲整体缩放或加厚后改名。

### 后续兵种

刀盾、弓、弩等可留作未来独立任务；本轮不实现新兵种、新武器、背旗、披风、多级 rank、战斗或 ECS 军队玩法。

## 检查与 GitHub 工作流

正式 GitHub Actions 仍只有：

1. Build & Core Checks
2. Targeted Numeric Checks
3. Manual Visual Review

不新增第四条“Soldier”永久 workflow。

`npm run check:soldier` 当前同时检查 S1/S2/S3 三套真实资产并保护 S0 契约：三种驻地风格、兵种维度、Recipe V5、七槽位、20 骨和退役军装不得回流。`Targeted Numeric Checks` 对 `src/soldier/**`、`scripts/check-soldier*`、本文件以及未来军装关键路径启用该检查。

从 S1 开始，真实甲胄还必须同时通过现有 wardrobe / tailoring / deformation / motion 检查，不能用军人专项替代原服装回归。S1已加入 `review:soldier` 与 Manual Visual Review 的 soldier scope；普通交互和显式截图分别验证，S0不生成空占位截图。

视觉验收至少包含：静态三分之四视角、正面、侧面、经营俯视，以及站立/行走/轻跑/坐姿或等价关键动作。S2 已加入宫卫/边军同机位双人对照；S3 追加同机位三人对照，验证不看文字也能区分皇宫、边疆、城市。

自动检查、截图生成、AI 实际看图和用户美术认可继续分别记录；有限关键帧通过不能写成全时域零穿插。

## 不做范围

本工作流不自动引入职业系统、军籍、军饷、战斗 AI、列阵、城防值、伤害、武器碰撞、Root Motion、Foot IK、布料物理、披风物理、万人 GPU Crowd 或 Unity ECS 士兵运行时。Web 只为外观资产和动画适配提供可靠作者基线。
