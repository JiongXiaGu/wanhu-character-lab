## 目标与数据所有权

军人第一视觉轴为甲装等级 `light / medium / heavy`，分别表达轻短灵活、标准正规军甲装、宽厚沉稳。驻地 `palace / frontier / city` 为第二轴，主要负责 palette 与头盔；身份只有 `soldier / captain`，只改变 headwear variant。重甲是一个中性、可染色的共享基底，不复制三份驻地专属近似甲。大轮廓和色块优先，不做魔幻巨肩。

`src/soldier/` 拥有试衣分类、配色和头盔选择；真实甲胄作者资产在 `src/character/wardrobe/assets/military/`，沿原封口和装配入口工作，不建立第二套生成器或 Renderer。首次从居民装进入驻地可应用该驻地默认套装；后续驻地切换不覆盖等级、混搭衣裤和装备。等级由实际 top + bottom 推导，混搭返回无完整等级；身份由 headwear 推导，不能独立保存第二份状态。

Recipe 保持 V5 六字段 `version / bodyType / slots / dyes / hairStyle / hairColor`，七槽位 `headwear / top / bottom / shoes / back / leftHand / rightHand`。不得加入 serviceStyle、armorClass、soldierIdentity、profession、role 或 rank。固定男女、20骨、最多双权重、inverse bind、Actor 生命周期、Renderer 数量、Mixamo/MediaPipe/GLB 链路、保存与染色协议不变。不增加肩甲骨、甲裙骨、动态肩甲或实时布料。

## Actions 执行与加速边界

只保留 Build & Core Checks、Targeted Numeric Checks、Manual Visual Review 三条永久 workflow。删除旧 one-shot-motion-evidence 和本轮临时诊断快照；不留下用于接手下载源码的任务。保留同分支过期运行取消和所有正式失败门槛。

Targeted 的军人检查不再串行互相阻塞：

- prepare-soldier 提取/验证动作一次，生成带真实候选SHA的输入包。
- soldier 执行原静态/衣柜/故障注入及原完整下身穿插，是完整穿插的唯一执行者；原通用 tailoring 任务仍执行 check-tailoring-v2，不重复跑同一穿插脚本。专用触发范围覆盖原全部tailoring输入。
- soldier-motion 按light、medium、heavy并行，fail-fast为false，各分片保留该甲装全部驻地/身份/性别/真实动作源键和中点。
- soldier-browser 的focused和full并行，均独立保留原入口，不与几何检查互相遮蔽。
- soldier-motion-coverage 汇总三份真实报告，要求相同SHA、三分片完整不重复、逐动作时间集合摘要一致、样本与总姿态计数相等。缺分片、旧SHA、失败报告、重复/少采样等9个故障反例必须被拒绝。当前27动作应为972个组合和467100个姿态；新增动作时按真实目录重建期望，不把历史数字当减采样目标。

缓存只保存动作提取输入，不缓存测试结果。缓存key覆盖原FBX/GLB文件、提取脚本/库、动作数据定义、目录、Node主版本、lockfile和缓存动作自身；不使用宽松restore-keys。命中后仍执行原prepare:motion的源哈希/目录验证与MediaPipe检查。军人下游只恢复本次workflow、同SHA输入包，校验SOURCE_SHA和git diff后测试。Build/Manual复用同一准备入口，build关闭重复prebuild调用，但不省略动作准备。

`node scripts/check-ci-graph.mjs` 随Build运行，防止重复/漏掉重要命令、错误分片、遗漏触发范围或恢复第四条workflow。原人物、衣柜、坐骑、家畜、动捕和浏览器回归保留。提速来自去重、复用输入和缩短串行路径，不宣称整条流程必然快3倍；实际时间取决于runner排队、缓存命中和最慢任务，应从新旧Actions日志比较。
