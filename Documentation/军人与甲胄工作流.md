# 军人与甲胄工作流

## 目标与边界

《万户天工》的军人外观采用泛中国古代军伍语言，以宋至明时期常见的札甲、布面甲、甲裙、护肩、盔缨等结构作为视觉参考，不绑定唯一朝代。第一层分类固定为皇宫、边疆、城市三种驻地风格；兵种和军阶是另一维度，不能把“驻地风格 = 兵种”。

Web 项目继续只验证人物外观、蒙皮、动作与中远景识别，不实现战斗数值、征兵、编制、AI、寻路、阵型、武器伤害或城防玩法。正式士兵身份、兵种、军阶与编制留给 Unity 运行时。

## 数据所有权与不变量

`src/soldier/contract.ts` 只拥有军人风格分类、计划资产 ID、首批制作顺序和基础配色，不建立第二套人物生成器。真实甲胄仍进入现有 `src/character/wardrobe/` 资产、装配、封口与染色链路；头盔、武器和背具继续使用既有对应槽位与作者路径。

人物 Recipe 保持 V5 精确六字段和七槽位：

- `headwear`
- `top`
- `bottom`
- `shoes`
- `back`
- `leftHand`
- `rightHand`

不得新增 `soldierStyle`、`profession`、`role`、`rank`、`armorSlot` 等字段。军装仍是一组普通外观资产，玩法身份不由外观配方决定。

人物继续使用现有 20 骨、最多双权重和同一套动作重定向；不增加盔甲骨、肩甲骨、甲裙骨或军人 Animator。旧 `guard_light_armor`、`archer_tunic`、`guard_pants`、`archer_pants`、`loose_trousers`、`boots` 已退役，不得为了军人功能恢复兼容。

## 三种驻地风格

| 风格 | 视觉职责 | 经营视角主轮廓 | 基础色 |
|---|---|---|---|
| 皇宫禁卫 `palace` | 宫门、宫城、仪仗与精锐守卫 | 宽肩、高盔、红缨 | 绛红 / 黑铁 / 暗铜 |
| 边疆戍卒 `frontier` | 长期驻防、城塞与野外军营 | 厚胸、长甲裙、护颈 | 深靛灰 / 旧铁 / 暗赤 |
| 城市守军 `city` | 城门、街道、仓署与日常巡逻 | 短甲、窄肩、明显腰带 | 青黑 / 灰铁 / 暗金褐 |

三类必须主要依靠轮廓和大色块区分，不能依赖胸口小纹样、文字或近距离花纹。皇宫不做高饱和“金甲”；边军不做破烂后末日风；城市守军不能只是皇宫甲换色。

## 计划资产 ID

| 风格 | 头盔 | 上甲 | 下装 | 鞋 |
|---|---|---|---|---|
| 皇宫 | `palace_guard_helmet` | `palace_guard_armor` | `palace_guard_skirt` | `military_boots` |
| 边疆 | `frontier_guard_helmet` | `frontier_lamellar_armor` | `frontier_armor_skirt` | `military_boots` |
| 城市 | `city_guard_helmet` | `city_guard_brigandine` | `city_guard_trousers` | `military_boots` |

这些 ID 在对应作者资产完成并通过数值检查前，不得提前加入 Recipe 合法 ID 或人物 UI，避免出现可选但没有真实模型的占位项。

第一件军用武器计划为 `military_spear`。现有 `guard_sword`、`guard_shield`、`archer_bow`、`archer_quiver` 暂时保留，不因为建立军人工作流自动重做或删除。

## 甲胄作者规则

上甲作为一个完整 `top` 资产制作胸甲、护肩、护臂和内衬，不拆成新的自由槽位。肩甲允许 Chest 与对应 UpperArm 的有限双权重，使抬臂时保持贴肩，但不能新增肩甲骨或逐帧碰撞。

甲裙作为一个完整 `bottom` 资产，但视觉上允许前左、前右、侧左、侧右、后左、后右的分片结构。主要权重来自 Pelvis 与左右 Thigh，避免制作完全刚性的圆筒甲裙。甲裙可以有真实分片缝隙，不套用连续布裙的“必须连续裙壳”规则。

头盔保持闭合、不透明、Head 刚性权重；只有经过明确建模的帽底可以隐藏头发，不能靠大范围穿头豁免。军靴仍走鞋槽和现有脚踝接口。

建议单套新增几何控制在约 700–1100 tris：头盔 100–180、上甲 280–420、下甲 180–280、军靴 60–100、单件武器 60–180。甲片节奏优先通过低模折面、分区和少量结构条带表达，不逐片堆叠几十个高成本小壳。

## 制作阶段

### S0：军人工作流与契约

本阶段只建立三类风格、计划 ID、作者边界、`check:soldier` 与 Targeted 作用域。不新增可见军装、不改人物 UI、不升级 Recipe。

### S1：皇宫禁卫第一套

先完成一名“皇宫禁卫 · 长枪”：

- `palace_guard_helmet`
- `palace_guard_armor`
- `palace_guard_skirt`
- `military_boots`
- `military_spear`

这一套负责验证红缨高盔、宽肩黑甲、分片甲裙、军靴、长枪、男女固定基模和现有 20 骨动作。只有真实资产与检查通过后再加入合法 ID、UI 和视觉审查入口。

### S2：边疆戍卒

在 S1 技术边界稳定后制作边军，不复制皇宫模型整体换色。重点验证厚胸、护颈、长甲裙和靛灰/旧铁轮廓。

### S3：城市守军

最后制作更短、更日常的城市布面甲/暗甲体系，重点验证短甲、腰带和城市场景中的居民尺度兼容。

### S4：兵种与军阶扩展

三套驻地风格稳定后再组合长枪、刀盾、弓手等兵种。军阶优先通过盔缨、腰扣和少量甲缘差异表达，不制造九套互不兼容的整身资产。

## 检查与 GitHub 工作流

正式 GitHub Actions 仍只有：

1. Build & Core Checks
2. Targeted Numeric Checks
3. Manual Visual Review

不新增第四条“Soldier”永久 workflow。

`npm run check:soldier` 当前负责保护 S0 契约：三种驻地风格、兵种维度、Recipe V5、七槽位、20 骨和退役军装不得回流。`Targeted Numeric Checks` 对 `src/soldier/**`、`scripts/check-soldier*`、本文件以及未来军装关键路径启用该检查。

从 S1 开始，真实甲胄还必须同时通过现有 wardrobe / tailoring / deformation / motion 检查，不能用军人专项替代原服装回归。S1 出现第一件可见资产后再加入 `review:soldier` 和 Manual Visual Review 的 soldier scope；S0 不生成“空军人”截图。

视觉验收至少包含：静态三分之四视角、正面、侧面、经营俯视，以及站立/行走/轻跑/坐姿或等价关键动作。三类风格全部存在后，必须增加同机位三人对照，验证不看文字也能区分皇宫、边疆、城市。

自动检查、截图生成、AI 实际看图和用户美术认可继续分别记录；有限关键帧通过不能写成全时域零穿插。

## 不做范围

本工作流不自动引入职业系统、军籍、军饷、战斗 AI、列阵、城防值、伤害、武器碰撞、Root Motion、Foot IK、布料物理、披风物理、万人 GPU Crowd 或 Unity ECS 士兵运行时。Web 只为外观资产和动画适配提供可靠作者基线。
