## 职责与不变量

第一视觉轴为甲装等级 `light / medium / heavy`；驻地 `palace / frontier / city` 为第二轴，只拥有 palette + helmet；普通/队长只通过实际 headwear 区分。Light 是城市短甲/束腿裤，Medium 是皇宫/边疆共享的 `medium_armor + medium_armor_skirt`，Heavy 是共享中性可染色的 `heavy_armor + heavy_armor_skirt`。不能复制三份驻地近似甲。

`src/soldier/` 拥有试衣分类、配色和头盔选择。真实甲胄由 `src/character/wardrobe/assets/military/` 作者资产沿原封口/装配入口生成；六款 Heavy 头盔在 `heavy-equipment.ts` 中沿原 ID 与试衣/preset 映射工作。首次从居民装进入驻地可应用默认套装，之后切驻地保留等级、混搭衣裤和装备；等级由实际 top+bottom 推导，混搭无完整等级；身份从 headwear 推导，不另存重复状态。

Recipe 精确保持 V5 六字段 `version / bodyType / slots / dyes / hairStyle / hairColor` 和七槽位 `headwear / top / bottom / shoes / back / leftHand / rightHand`。固定男女、20骨、最多双权重、inverse bind、Actor 生命周期、Renderer 数量、动捕、保存与染色协议不变。不加甲裙/肩甲骨、动态肩甲、实时布料、运动相位特例或游戏职业/军阶字段。队长顶饰继续细高、居中、收尖，禁止恢复宽短缨、肥厚后拖与横向大冠。

已退役的 `palace_guard_armor / frontier_lamellar_armor / palace_guard_skirt / frontier_armor_skirt` 以及更早军服 ID 不恢复至 Recipe/UI，不迁移旧 JSON。历史 S0至S5 的几何、预算与执行记录查 Git 历史，不作为当前候选成功证据。三驻地和普通/队长职责见各自专篇。

## Fast / Candidate / Release

永久 workflow 精确只有 Build & Core Checks、Targeted Numeric Checks、Manual Visual Review。不得新增第四条 Heavy workflow、临时 one-shot、永久调试 workflow。范围裁剪只通过既有 scope 和 Draft / Ready 完成，不能削减发布采样或断言。

Fast：任务分支手动选择 Targeted 的 `soldier-heavy-authoring`，只跑作者静态契约，不准备动作、不启动浏览器。看轮廓选择 Manual 的 `soldier-heavy-fast`，只生成 `heavy-front.png / heavy-side.png / heavy-back.png / medium-vs-heavy-front.png` 四张原 WebGL 图。方向不成立就修作者，不启动完整 Release。

Candidate：Fast 成立后选择 `soldier-heavy-candidate`；Heavy-only Draft 的 opened/synchronize/reopened 自动先 Fast，成功才进入 Candidate。保留 Soldier static 和原完整 lower-body intersections；该原脚本仍覆盖所有下装/源键/中点，不另造挑帧检测器。只运行 Heavy motion 与 focused fitting browser，不运行 Light/Medium motion、full browser 或完整 coverage。带 `[soldier-visual]` 的 Heavy-only Draft 自动只生成四张 Fast 预览。

Release：Candidate 真正通过后才转 Ready。Targeted 与 Manual 显式监听 `ready_for_review`，Ready触发完整 Soldier static、full lower-body intersections、light/medium/heavy motion、motion coverage、focused/full browser；正式视觉使用 `soldier` / `[soldier-visual]` 完整矩阵。main push继续正式回归。不能先要求 Release 成功才转 Ready，也不能拿 Candidate/Fast 冒充发布 Gate。Build & Core 的基础检查保留。

分流检查整个 PR 与 merge-base 的差异，不能只看最新提交。Heavy 作者和随其几何同步的明确静态契约可进入候选；`check-deformation.ts / check-lightwear.ts / check-soldier-assets.ts / check-soldier-wardrobe.ts` 仅可同步 Heavy 作者断言，不可借白名单改共享算法/删其它资产断言。shared rig、Recipe、assembly、motion、通用变形、Renderer、交点算法/豁免、workflow、package 或未知源码路径自动扩大到 Release，手动指定 Heavy scope 也不能绕过。

Heavy 专属作者文件由 soldier lane 拥有，不仅因处于 wardrobe 目录就扇出 riding/mounts；共享文件变化仍按真实影响回归。缓存只保存动作提取输入，不缓存测试结果。三 motion shard只是外层组合拆分，全部动作源键/中点、实际蒙皮函数、容差与断言不变，coverage必须拒绝缺片、重复、过期 SHA 或缺姿态。`check-ci-graph.mjs` 随 Build 保护三个永久 workflow、Fast依赖、Candidate/Release矩阵及共享改动升级行为。

## Actions 执行纪律与合并

**不高频轮询 ≠ CI 未完成就停止任务。** 提交后先确认正确 SHA 和 workflow 已启动，不连续按 workflow→jobs→steps反复读取。runner工作时继续模型、文档、截图、冲突与合并准备。Fast/Candidate失败只查真实失败 job/step/log/artifact，修对应作者，不启动无关完整矩阵。

Release 或 main复检成为唯一依赖时，优先单次 watch/持续等待；无此能力才低频读取。queued/in_progress本身不是结束条件。只有 workflow自身timeout、连续约20分钟无进展且没有其它工作、真实GitHub/执行/权限硬阻塞，或用户要求停止，才能交回未完成状态。failure/cancelled/action_required要读真实原因并修复，不能用其它成功掩盖失败。

正式完整 Gate成功且最终图实际打开后，重读实时 main和PR head，保留并行工作，以 expected head SHA正常merge，不force、不reset。合并后核对 main SHA/PR merged和main实际Build/Targeted终态。文档收尾记录候选SHA、merge/mainSHA、各run/conclusion和实际打开图；纯文档差异明确说明，不伪称每张图来自文档提交的另一SHA。

本轮不做新军种/武器、披风/背旗、多级军阶、战斗/伤害/阵型/ECS军队、Root Motion、Foot IK、万人GPU Crowd或Unity正式士兵玩法。
