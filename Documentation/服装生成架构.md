# 服装生成架构

## 1. 目标

《万户天工》的居民数量大，角色面数预算和每帧动画成本都必须受控。

服装系统的目标不是模拟真实布料，而是：

- 在极低面数下形成清晰服装轮廓；
- 适配不同身高、胖瘦、肩宽和四肢比例；
- 与统一人体骨架共用蒙皮语义；
- 穿衣后隐藏被覆盖的人体面；
- 最终尽量合并为一个 Skinned Mesh；
- 服装内容保存为 Recipe / Template 数据，而不是每个款式一个最终 FBX / GLB；
- Web 与 Unity 使用同一套服装语义，生成实现分别使用 TypeScript 与 C# / Burst。

默认不做实时 Cloth Simulation。

长袍、裙摆、宽袖等需要轻微动态时，优先使用少量辅助骨骼或 Shader Secondary Motion，而不是布料求解器。

## 2. 人体对服装系统的前置要求

服装不能建立在当前“独立棱柱拼接人体”上。

V2 基础人体目标改为：

Continuous Low-Poly Base Body

它仍然必须低面数，但需要：

- 身体表面连续；
- 肩、肘、髋、膝、颈等区域有最小可用关节拓扑；
- 固定、稳定的 Vertex / Face 语义；
- 可被运行时参数变形；
- 有稳定的服装锚点；
- 每个 Body Face 能标记所属区域，用于穿衣时隐藏。

连续人体不意味着回到旧的高分段 Ring / JointPatch 方案。

目标是一个固定低模 Cage，拓扑长期稳定，只改变顶点位置。

## 3. Body Surface 语义

基础人体至少定义三层语义。

### HumanLandmarks

描述人体关键位置，例如：

- Neck
- Shoulder
- Chest
- Waist
- Hip
- Elbow
- Wrist
- Knee
- Ankle

Landmark 同时服务于 Base Body、Rig、Garment、LOD 和 Debug Review。

### Garment Anchor Loops

在稳定人体拓扑上定义少量服装锚点环，例如：

- NeckLine
- ChestLine
- WaistLine
- HipLine
- UpperArmLine
- ElbowLine
- WristLine
- ThighLine
- KneeLine
- AnkleLine

服装 Recipe 引用这些语义锚点，不直接依赖某个 Web 顶点数组的临时编号。

### Body Face Groups

人体 Triangle / Quad 按覆盖区域分组，例如：

- Head
- Neck
- Chest
- Back
- Abdomen
- Pelvis
- UpperArm
- LowerArm
- Hand
- UpperLeg
- LowerLeg
- Foot

穿衣时由 Recipe 指定需要隐藏哪些 Face Group。

最终 Mesh Assembly 直接跳过被覆盖的人体 Triangle，而不是完整裸体 Mesh 与衣服一起渲染。

## 4. 四类服装生成方式

所有服装先归入以下四类，不使用一套算法硬做所有款式。

### A. Material Only

适合几乎不改变轮廓的内容：

- 贴身内衣；
- 裹布；
- 极薄袜类；
- 身体纹样。

不创建额外服装 Mesh，只改变 Material Role / UV / Pattern。

额外 Triangle：0。

### B. Body-Derived Garment

适合普通上衣、窄袖衣、裤子、贴身外衣、护腿等。

从连续人体的稳定 Surface / Anchor Loop 派生低模服装。

两种模式：

Replace：
服装直接替代被覆盖的人体 Surface。适合非常贴身的衣服。不保留衣服下面的裸体 Triangle，因此几乎没有重复几何。

Offset：
复制少量人体语义 Surface，并通过 Normal Offset、Width / Depth Ease、Sleeve Length、Hem Length 形成比人体略宽松的轮廓。仍然隐藏下方人体 Face。

Body-Derived Garment 应优先复用人体骨骼权重。

### C. Independent Silhouette Garment

适合真正改变人物轮廓的服装：

- 长袍；
- 裙；
- 宽袖；
- 外套；
- 披肩；
- 宽腿裤。

这类服装不能简单把人体 Surface 向外推。

使用少量独立 Garment Loop / Section 生成低模 Cage，例如：

~~~text
Waist
→ Hip
→ Knee
→ Hem
~~~

每个截面只使用少量顶点，例如 4 / 6 / 8 个。

长袍下摆不追求真实布料褶皱，只需要正视轮廓成立、侧视厚度合理、动画时不明显穿腿、面数低。

### D. Rigid Attachment

适合帽子、发簪、腰带、鞋、护腕、小型配饰。

使用极低面数独立生成，并绑定到单 Bone 或少数 Bone。

例如：

- Hat → Head 100%
- Belt → Pelvis / Spine
- Shoes → Foot 100%

不使用 Cloth Simulation。

## 5. GarmentRecipe

服装的正式内容源不是最终 Mesh，而是 GarmentRecipe。

建议长期包含：

~~~text
GarmentRecipe
├─ id
├─ category
├─ generationMode
├─ anchorLoops
├─ coverage / hideBodyGroups
├─ length
├─ ease
├─ widthProfile
├─ depthProfile
├─ sleeveProfile
├─ hemProfile
├─ bonePolicy
├─ materialRole
└─ lodProfile
~~~

普通短上衣示例：

~~~text
generationMode = BodyDerived.Offset
anchors = NeckLine / ChestLine / WaistLine / WristLine
hide = Chest / Back / Abdomen / UpperArm
ease = 0.04
bodyLength = 0.72
sleeveLength = 0.86
~~~

长袍示例：

~~~text
generationMode = IndependentSilhouette
anchors = Shoulder / Waist / Hip
hide = Chest / Back / Abdomen / Pelvis / UpperLeg
hem = Ankle
bonePolicy = PelvisAndLegs
~~~

## 6. 服装如何适配不同体型

不要为每一种体型重新保存服装 Mesh。

服装应基于标准 Recipe + 当前人体语义重新生成。

紧身或普通服装优先采用：

~~~text
Body Surface Triangle
→ barycentric / semantic mapping
→ garment offset
→ final garment vertex
~~~

独立轮廓服装则使用：

~~~text
HumanLandmarks
+ Anchor Loops
+ Garment Profile
→ garment sections
→ final garment mesh
~~~

也就是说：

- 人体决定服装在哪里；
- Recipe 决定服装长什么样；
- 当前身材决定服装最终尺寸。

这里参考 MakeHuman / MakeClothes 的 Body-to-Clothes Mapping 思路，但本项目只吸收概念和数据设计，不依赖其最终高面数人体资产。

## 7. 蒙皮策略

服装不需要与裸体人体拓扑焊接，但必须与人体共享 Skeleton 和稳定的权重语义。

### Body-Derived Garment

直接继承或重新采样对应 Body Surface 的权重。

### 普通袖子

只允许少量 Bone：

- UpperArm
- LowerArm

关节附近最多 2 Bone Blend。

### 裤腿

只允许少量 Bone：

- UpperLeg
- LowerLeg

### 长袍 / 裙摆

默认不做 Cloth。

优先方案：

- 上部 → Pelvis / Spine；
- 左下摆 → Pelvis + LeftUpperLeg；
- 右下摆 → Pelvis + RightUpperLeg。

如果近景动作仍明显僵硬，LOD0 才允许加入极少量 Garment Helper Bones。

不要一开始就给所有 NPC 添加大量 Cloth Bones。

## 8. Secondary Motion

实时布料模拟不是默认功能。

按成本从低到高：

~~~text
完全骨骼驱动
→ Shader Sway
→ 1~4 Helper Bones
→ 真正 Cloth Simulation
~~~

正式大规模居民默认停留在前两级。

只有极少数近景特殊角色才考虑更高等级。

## 9. Body Hide

这是服装系统的硬要求。

错误方案：

~~~text
完整裸体 Mesh
+
完整衣服 Mesh
~~~

会导致重复 Triangle、穿模、Z-Fighting、Skinning 浪费和 Overdraw 增加。

正确方案：

~~~text
Body
+ GarmentRecipe.hideBodyGroups
→ Visible Body Faces
+ Garment Mesh
→ Final Mesh
~~~

最终只保留实际能看到的表面。

Body Hide 应在 Mesh Assembly 阶段完成，而不是 Renderer 层关闭整个 BodyPart。

## 10. 面数预算

面数预算按“最终可见人物”计算，而不是裸体人体 + 每件衣服分别计算。

| 内容 | 建议 Triangle |
| --- | ---: |
| V2 连续基础人体 | 350–500 |
| 普通 Body-Derived 上衣 | 60–120 |
| 普通裤子 | 50–100 |
| 长袍 / 裙 | 100–220 |
| 宽袖一对 | 40–100 |
| 鞋一对 | 20–50 |
| 帽子 | 20–80 |

由于衣服会隐藏对应 Body Faces，普通穿衣居民最终不会简单等于以上数字相加。

初始整体目标：

~~~text
LOD0 普通居民：约 450–700 tris
LOD0 复杂服饰：约 600–900 tris
LOD1：约 250–400 tris
LOD2：约 100–200 tris
极远：Impostor / Billboard
~~~

这些是设计目标，不是最终性能结论；最终仍以 Unity 实机 Profile 为准。

## 11. 古代服饰的推荐实现

内衣 / 贴身衣：
Material Only 或 Body-Derived Replace。

普通短衣 / 窄袖袍：
Body-Derived Offset。

裤子：
Body-Derived Replace / Offset。

长袍：
上身可以 Body-Derived，下半身使用 Independent Silhouette。不要把整件长袍强行做成一个人体外扩壳。

裙：
Independent Silhouette。

宽袖：
Independent Silhouette，锚定 UpperArm / LowerArm。

腰带：
Rigid Attachment。

帽子：
Rigid Attachment。

鞋：
Rigid Attachment，或直接替换 Foot 外观。

## 12. 美术制作方式

“运行时生成”不等于“不能由美术人员设计”。

推荐工作流：

~~~text
标准人体
→ 在 Web / Blender 中设计服装参考轮廓
→ 标记 Anchor / Profile / Coverage
→ 导出 GarmentRecipe
→ 游戏运行时按当前人体重新生成
~~~

可以保存：

- 控制点；
- Profile；
- Anchor；
- 宽松度；
- 长度；
- Material Role；
- Body Hide Mask；
- Bone Policy。

不保存：

- 每个居民的最终衣服 Mesh；
- 每个体型一个独立 FBX；
- 每个 LOD 一套手工服装资产。

后续可以制作 Blender / Web Garment Recipe 编辑器，提高美术效率。

## 13. Review 规则

服装不能只在 T Pose 看。

每件基础服装至少检查：

- Front Orthographic；
- Side Orthographic；
- Back；
- 3/4；
- Wireframe；
- Body Hide；
- 抬手；
- 屈肘；
- 抬腿；
- 屈膝。

必须同时看外轮廓、衣服与身体间距、是否出现裸体穿出、关节是否露缝、Body Hide 是否过多、Triangle Budget。

## 14. 当前实现顺序

先不要直接开发大量服装。

顺序固定为：

~~~text
V2 Continuous Low-Poly Base Body
→ Stable Body Surface Groups
→ RigDefinition V1
→ Skin Weight V1
→ Garment Anchor Loops
→ Body Hide
→ Body-Derived Shirt
→ Body-Derived Pants
→ Independent Robe
→ Rigid Hat / Shoes
→ LOD / Cache
~~~

第一批只验证四件：

- 短上衣；
- 裤子；
- 简单长袍；
- 帽子。

这四类跑通后，再扩展具体古代服饰。
