# 模块化服装生成架构

Recipe V5 → patterns注册 → 独立衣裤裙鞋 → 固定皮肤覆盖 → 一个最终网格 → 同一套20骨骼。固定人体不负责服装轮廓，只在换装时装配；不逐帧碰撞求解或生成网格。

## 职责与数据所有权

patterns.ts注册9上衣与11下装的固定资产，提供专用资产ID、接口和低运动边界。assets/contract.ts定义GarmentPiece、覆盖区域和明确开口；服装几何版本wanhu-modular-garments-v7，覆盖契约wanhu-authored-coverage-v1。

tops.ts负责上衣分派；work-shirt、cross-shirt、half-sleeve、work-vest、short-jacket各自拥有衣身、领袖、门襟、色区与静态权重。top-seams只提供有限缝片操作，不能以统一宽度参数冒充新服饰。

trousers.ts负责下装分派及原长裤腰臀、腿根和有限宽裆底。authored-legs保留直筒／束脚制作表；short-bottoms拥有封口短裤和旧分片裙裤。skirts.ts独立制作真正连续短裙和素面长裙，不调用裤腿或源皮肤构造器。

两条真裙采用12段连续环、前后跨中线、固定厚裙边和12片简单封底。它们不是超宽裤腿、外贴片、内裤叠层或复杂里衬。所有权重一次写入，每顶点至多双权重，共享原骨架，不能新增裙装Animator或裙摆骨链。

footwear负责鞋与脚踝接口。assembly只按固定covers装配可见皮肤及服饰，再剔除未引用顶点；不改源皮肤，不读取动作或临时删面。本轮没有修改assembly。v3/outfit负责脸、发饰与工具总装配，本轮未改。adornments／headwear-fit维持第二批冠髻与一次性帽壳留量，不为裙装顺手改发型。

## 固定覆盖和开口

| 类型 | 隐藏的源皮肤 | 必须保留 |
|---|---|---|
| 第一批劳作短衣 | torso、upperArm | forearm、手 |
| 交领常服／半臂内袖 | torso、upperArm、forearm | 手 |
| 背心／短褂 | torso | 原上臂、前臂、手 |
| 长裤 | pelvis、thigh、shin | foot由鞋决定 |
| 短裤／旧裙裤／真短裙 | pelvis、thigh | 原shin；foot由鞋决定 |
| 素面长裙 | pelvis、thigh、shin | foot由鞋决定 |
| 鞋 | foot | 对应脚踝接口 |

短裙外缘与源膝上边界固定衔接；长裙不恢复内部腿部绘制。女性使用既有固定映射一次。覆盖来自资产，不能写成“所有上衣遮上臂”“所有下装遮小腿”。

上衣声明腰、领、双袖窿／袖口；裤装腰和两裤口；鞋双脚踝。新裙装封底后只声明腰口，另以closedHem锚点保存裙边。未声明破洞、重复面、非流形、坏权重仍报错。旧裙裤仍有两个独立裤管和完整裆底，不冒充真裙。

## 制作接口与动作边界

短裤的厚断面保留腿穿出的开口，不以实心圆盘切穿膝盖。真裙固定封底与腿出口／末端裙边的数学接触属于专门制作接口；离线检查先计算全部原始交点，再由garment-contact-scope.ts窄范围分类，报告保留原始与分类计数。该脚本不进入运行时，不执行碰撞修正。

只有两个新裙子的HemCenter扇面与末端Hem/HemInset/HemFacing或皮肤shin可列为接口。Calf、腰臀、裙身、上衣、大腿及任何旧服装不豁免。普通动作其他穿插继续阻塞。stressOnlyClips仅对新裙装标明Snatch深蹲举重压力片段，源帧与中点仍全量检查；它不是独立Animator或测试采样删除开关。

普通站立、行走、起步、轻跑、坐姿是裙装用途，极端开腿／高踢／翻滚不保证零穿插。完整制作细节见《短裤封边与连续裙装.md》。

## 预算、染色与验证

男女原皮肤各524三角形，绑定和保护签名不刷新。第一批上衣220／290／340、长裤272／304，其余旧长裤220保持；背心102、短褂174保持。当前短裤176、真短裙180、长裙252、旧裙裤176三角形。

primary／secondary／accent仍作为面颜色进入缓存，染色不改坐标、拓扑、覆盖或权重。不存在外部DCC通用服装导入器、跨染色网格共享或GPU万人运行时。

原身体／绑定、旧服装组合、源FBX、压力姿态、源键和中点检查全部保留。新裙装增加连续性、封底、左右色区、接口分类故障注入与16套要求混搭；完整贯穿24,216样本保留原20,180严格样本，不降低容差。

六条正式Actions保持；新裙装并行job追加到Modular，原compare和两批矩阵不减少。自动检查、真实图片生成与实际人工查看必须分别记录，具体SHA、run和抽查范围见《工作交接.md》。
