# 骑乘与坐骑挂接

## 目标与边界

M2将现有V5人物与M1马组合为可试衣的骑乘预览。复用两个固定成年男女、现有衣柜与马本体；不新建骑手专用人体，不把马加入人物七槽位。Recipe仍只有version、bodyType、slots、dyes、hairStyle、hairColor六字段。

本轮提供静态跨坐、停驻、步行和奔跑。骑手动作是本项目制作并烘焙的局部轨道，不是新增Mixamo FBX。原人物工坊仍只使用静态绑定与原FBX试衣；骑乘轨道不是FBX失败回退，也不恢复已删除的程序劳动动作系统。

没有上下马、马具、缰绳、手指握持、实时IK、地形贴蹄、导航、玩家移动、骑射或马车。Horse_Eat只在马匹本体页保留，不建立骑乘吃草配对。

## 挂点与绑定空间

坐标统一为米、+X右、+Y上、+Z前。挂接关系为Horse Spine → RiderSeat → RiderRoot → 人物SkinnedMesh。RiderSeat是普通Group，不插入马的25骨骼调色板。

Seat局部偏移沿用M1预留初值(0,0.35,0.12)，绑定世界约(0,1.65,0)。该点代表坐面参考，不是人体Hips骨原点。男性骨盆相对坐面抬高0.13米，女性0.12米；RiderRoot减去各自绑定Hips位置后附加该制作距离。代码中的RIDER_FIT是当前校准实现，不把两组偏移复制为新的配方字段。

Actor必须先在自己的原点和真实绑定空间创建，再挂接整个人物。挂接后不重新bind、不重新计算inverse bind、不调用Skeleton.pose来代替骑姿。测试必须包含整马平移、旋转和等比缩放，避免只在原点碰巧对齐。骨架Helper保持正确的世界变换，不能再放进Seat重复应用父变换。

## 骑姿与时间

静态骑姿使大腿向外跨坐、膝盖下降、小腿位于马腹两侧、脚向前；男女依据自己的绑定尺寸制作。躯干有限前倾，双臂放松前伸；当前没有精确握缰目标。

Rider_Idle配Horse_Idle，Rider_Walk配Horse_Walk，Rider_Run配Horse_Run。时长直接读取马定义，不另存一份容易漂移的时长。动态片段按30fps烘焙完整首尾，每片段只写现有20骨骼的局部四元数，不写根平移或缩放；静态骑姿也通过固定轨道采样。

马背的升降和旋转由父子挂接提供。骑手轨道只做有限躯干缓冲，不再复制马骨盆位移。作者层可在烘焙时读取对应马姿态进行低幅俯仰补偿；播放阶段不执行IK、腿目标求解或几何生成。

HorsePlayer是唯一时间所有者。每次先推进／定位马并更新Spine世界变换，然后用同一相位采样骑手。骑手没有独立累加器。暂停、逐帧、变速、循环、单次末帧保持和重播均由这一条链路处理。

## 换装与生命周期

进入页面创建一匹马和一个骑手。切换动作、相机、材质、暂停和拖动时间不重建几何。改V5配方时先成功构造新骑手及其轨道，再移除和释放旧骑手，挂上新对象并恢复当前相位；马、播放时间、循环设置和相机不随换装重置。

退出页面必须停止RAF、断开ResizeObserver、释放两套Mixer／Skeleton、几何、材质、Helper、相机控制器及渲染器。dispose可重复调用；不得残留第二个时钟或隐藏骑手。

只从wanhu.character.wardrobe.v5读取玩家明确保存的装扮；没有保存时给出提示，不猜测另一个页面未保存的状态。外部JSON继续经parseRecipeFile严格验证，超过32KB、旧版本及退役资产拒绝。骑乘编辑不静默覆盖人物工坊存档。

## 页面入口与服饰边界

main运行后：人物工坊 → 动物工坊 → 右侧“骑乘试衣”。直接入口为?lab=riding，静态入口为?lab=riding&clip=pose&paused=1；可用bodyType=female切换初始骑手。相机工具在预览区右上，循环播放在底部且默认开启。

现有7上衣、5下装和布鞋都可以选择并构造。裤装作为第一轮骑姿验收基准。两条连续封底裙仍可试穿，但跨坐可能与马背／马腹穿插；UI必须明确提示实验边界，不自动换裤装、拆开裙壳、删除封底或随动作删皮肤。手持物保持原配方，不能把保留道具误写为已支持骑射或持工具劳动。

## 自动检查与证据边界

npm run check:riding覆盖双基模、三动作各241相位，共1446个稠密动态姿态；另检查静态、循环首尾、末帧保持、重播、逐帧、非法时间、实例变换、暂停换装、inverse bind保护和资源释放。70种现役男女衣裤组合还会分别采样静态及三动作五个相位。

检查骨盆相对Seat误差、膝脚粗范围、骨矩阵及真实蒙皮顶点有限性，并对真实SkinnedMesh路径核对父变换只应用一次。四类故障注入分别为相位不同步、挂点脱离Spine、骨盆漂移和NaN；男女各执行一次。故障注入必须明确失败，不把故障数值混入正常运行统计。

npm run check:riding-browser使用真实桌面Chromium验证一级／二级入口、两套骨架、动作与网格复用、男女与换装保相位、严格导入、存档不被改写、裙装提示、相机、播放和循环。该脚本不生成截图。

骑乘检查并入Targeted Numeric Checks，产物为riding-m2-checks，报告写明实际sourceSHA；没有新增永久workflow。原人物、服饰、FBX和马数值门槛不降低。人工截图继续按需进行，不因新增骑乘自动启动旧全量视觉矩阵。

上述检查不是逐三角马身／服装相交证明，不是所有连续时刻零穿插，也不是骑姿美术已验收。自然程度、近景裆部、膝部折面、衣摆与马腹接触仍由用户在网页判断；不能用CI绿色替代视觉结论。
