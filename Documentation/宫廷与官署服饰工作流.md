## 一、单轮工作量

默认一轮只做 **1 个正式可穿戴 ID**。只有两个或三个强关联部件必须组合才能形成新剪影、分开无法正确验收时，才允许作为一个小套装；最多 2–3 件。

合格例外包括宫女短襦 + 高腰长裙、皇后大袖外衣 + 宽摆宫裙、长礼袍 + 结构必需下裳。皇帝/皇后从冠、袍、裙、鞋到附件的五六件整套，多个品级/配色变体，或同轮填两个无关缺口均不允许。单件能表达独立剪影就拆成单件轮次。

## 二、轮廓差异门槛

新增服饰首先是新形，其次才是颜色、纹样和材质。统一灰色/素模下，必须与同槽位最近似资产在至少两个结构维度上明显不同：衣长、袖型/袖宽、肩部体量、腰线、下摆、层数/垂片、前后长度、领口/开襟、头饰延伸、鞋履体量。

颜色、纹样、亮度与同形附件换色不计入结构差异。PR 写明最近似资产、至少两个差异、去色后的辨识方式、填补哪个 WARDROBE_GAPS 或为何是真实新缺口。只能说明“更华贵”“换了纹样”的资产不合格。

## 三、人物视觉语言

这些只是设计方向，不是 Recipe 身份限制。

- 皇帝：纵向、长身、宽袖、厚重、最高等级；不能把短礼衣染黄冒充帝王袍。
- 皇后：横向体量、多层、大裙摆、大型冠饰；不能只用 long_skirt + jade_pin。
- 官员：规整、克制、正式、宽松；品级优先复用版型与局部细节，不逐级复制近似 Mesh。
- 太监/内侍：窄肩、收袖、窄长下摆与独立帽冠，主动区别官袍。
- 宫女：轻、短上身、长下身，低于皇后层级；窄袖与轻量两件式优先。

## 五、接手与登记

开始与合并前都重新读取最新远端 main、任务分支和 PR，不用聊天旧 SHA 覆盖并行提交。

先读 AGENTS.md、README、工作交接、服饰版型目录、本工作流、服装生成架构、固定基模与换装 V5，以及最接近的资产专题与作者代码。确认本轮单件/小套装、真实缺口、同槽位参照及至少两项结构差异，再实现，不预注册未来空 ID。

真实资产同步接入 types.ts、patterns.ts 或对应分派、SLOT_OPTIONS、WARDROBE_TAXONOMY、WARDROBE_GAPS、数值检查和专题文档。不能新增 ID 却漏登记 taxonomy；已有覆盖检查继续拦截。

## 六、实现边界

保持 Recipe V5 六字段、七槽位、成年男女、20 骨、最多双权重、一个装配网格、自由混搭和三色染色只改色。没有实时布料、裙摆骨链、职业/阶级字段或宫廷玩法。

真正长袍可跨 pelvis/thigh/shin，但必须明确覆盖与动作检查，不为长衣另造人物协议。与独立 bottom 同穿必须检查真实组合，不假设 top 只到腰。推荐组合不等于套装锁定。共享运行时未改时，不因一件衣服扩大为全项目重做。

## 七、数值与动作验收

至少运行 TypeScript/production build、闭合/非流形/退化面/权重、固定男女/20 骨/双权重、染色几何不变、taxonomy、结构差异、真实蒙皮与相关贯穿检查。原采样、容差、故障注入和无关资产检查不降低。

检测后可以按可见性、衣层和动作性质分级：通常日常源键外层自交/穿体仍为 Hard；隐藏端面、层间数学接触、仅中点命中及显式资产 stress-only 保留 Warning。stress-only 必须登记在版型，仍完整采样，不能按失败结果临时跳过。

Warning 必须保留完整命中记录并审图。除上方明确登记的 C2/C4 公共动画手/下身接触外，可见外层破面、翻面、刺出和坏形仍应升级为模型阻塞。不能把一件裙子的 stress-only 借给上衣自身错误。

## 八、视觉验收

自动通过不能代替真实 WebGL 看图。必须针对本轮新 ID 定向截图，不用旧固定 wardrobe 图矩阵冒充新资产证据。

最低包含男女、正/侧/背/三分之四、统一素模、最近似资产同机位对照、日常动作，以及长摆/宽袖/裙装最易暴露问题的相位。小套装每件必须独立展示，同时保留组合图。

C2 修形以站姿轮廓为主。数值采样不减；Hard 保留失败组合的最坏相位图，Warning 可按性别/原因选真正最坏帧以去掉重复图，不选安全帧、不删完整诊断。原始 Canvas 保留；联系表不能变相换机位或比例掩盖问题。

必须实际打开新原图，关键截图直接贴最终对话。分别记录自动检查、截图生成、AI 实际看图和用户最终主观确认。

## 九、GitHub 交付

只保留原三条正式 Actions。沿当前任务 PR 完成作者资产 → 快速数值 → Build & Core Checks / 路径相关 Targeted Numeric Checks → 原 Manual Visual Review 定向图 → 实际审图 → 只修本轮问题 → 重读 main/head → 正常合并 → 确认 main 基础检查 → 更新工作交接。

不强推覆盖并行提交。检查失败只看对应日志。不要高频轮询，也不要因 Actions 仍在运行就把“提交候选”当成完成；等待时继续可完成的代码审查和文档，所需 Gate 完成后继续合并。不要重复为同一未变化作者资产主动跑无关全量美术矩阵。

## 十、完成定义

范围未扩张，真实新几何具备结构差异，登记/缺口同步，所需检查通过，新截图实际看过并直接交付，PR 正常合入最新 main，工作交接记录准确，且未把用户美术确认伪写成自动验收。

用户最终主观确认是独立后续状态，不是本轮已授权正常合并的额外前置条件。每轮完成后停止，不在同一个 PR 顺手开始下一件。
