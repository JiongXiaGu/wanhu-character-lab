# 宫廷与官署服饰制作工作流

本工作流用于皇帝、皇后、官员、太监、宫女及相关正式服饰的后续制作。它只约束衣冠工坊的作者资产、检索、验证与交付，不引入职业玩法、身份字段或套装锁定。

当前版型事实先查《服饰版型目录》和 `src/character/wardrobe/taxonomy.ts`。代码仍是实现权威。

## 一、单轮工作量

默认规则：

> **一轮只做 1 个正式可穿戴 ID。**

只有当两个或三个部件必须组合后才形成一个独立的新剪影，并且拆开制作会导致无法正确验收时，才允许按“1 套”处理。

一套最多 **2–3 个强关联部件**。例如：

- 宫女短襦 + 高腰长裙；
- 皇后大袖外衣 + 宽摆宫裙；
- 某件长礼袍 + 与其结构上不可分的正式下裳。

以下不算一套，禁止一次完成：

- 皇帝从冠、袍、下裳、鞋、腰带到附件的完整五六件组合；
- 皇后全部头饰、外衣、内衣、裙、鞋同时制作；
- “顺便”新增多个官员品级、多个宫女变体、多个配色版本；
- 同一轮同时填两个互不相关的版型缺口。

如果单件已经能独立表达新轮廓，就必须拆成单件轮次。

## 二、轮廓差异门槛

新增服饰首先是“新的形”，其次才是颜色、纹样和材质。

在统一灰色／素模状态下，与同槽位最接近的现有服饰相比，必须至少有 **2 个结构维度**形成明显差异：

1. 衣长／覆盖长度；
2. 袖型或袖体宽度；
3. 肩部宽度与体量；
4. 腰线位置与收束程度；
5. 下摆宽度／展开量；
6. 层数与前后垂片关系；
7. 前后长度关系；
8. 领口／开襟的大结构；
9. 头饰高度、宽度、帽檐、顶部、侧向或后向延伸；
10. 鞋履帮高、鞋头与整体体量。

颜色、纹样、材质亮度、同形附件换色不计入这两个结构维度。

每轮 PR 必须写明：

- 最近似的现有资产是谁；
- 本件至少哪两个结构维度与它不同；
- 去掉颜色后如何辨认；
- 它填掉 `WARDROBE_GAPS` 中哪个缺口，或为什么是新的真实缺口。

如果只能写出“颜色更华贵”“纹样不同”“更像皇帝/官员”，说明轮廓仍不合格。

## 三、人物视觉语言

这些只是设计方向，不是 Recipe 身份限制。

### 皇帝

关键词：**纵向、宽袖、厚重、最高等级**。

优先语言：高冠、长身礼袍、明显前后垂摆或大袖体量。不能把现有 `ceremony_robe` 换成黄色后视为皇帝服。

### 皇后

关键词：**横向体量、多层、大裙摆**。

优先语言：大袖外衣、多层披衣、宽摆或多层长裙、大型冠饰。不能只用 `long_skirt + jade_pin`。

### 官员

关键词：**规整、克制、正式、宽松**。

重点是规则长袍与官帽语言。官阶内部优先复用版型，通过帽饰、局部附件、色组等变化，不按品级重复制作近似 Mesh。

### 太监／内侍

关键词：**窄、长、收、利落**。

与官员主动做反差：更窄肩、更收袖口、更克制的下摆和独立内侍帽冠。不能直接使用官袍换色。

### 宫女

关键词：**轻、短上身、长下身、层级低于皇后**。

优先“短襦 + 高腰长裙”或轻量窄袖长衫。头饰小而成组，不与皇后共享大型体量。

## 四、建议制作队列

这是优先级，不是一次性任务。每轮只取其中一项。

| 阶段 | 类型 | 服饰目标 | 主要新轮廓 |
|---|---|---|---|
| C1 | 单件 | 窄袖直身长袍 | 真正长身、窄袖、可读束腰、小展长下摆 |
| C2 | 套装候选 | 宫女短襦 + 高腰长裙 | 极短上身 + 抬高腰线 + 长下身 |
| C3 | 单件 | 正式官帽 | 明确横向官署头部轮廓 |
| C4 | 单件 | 收袖内侍长衣 | 窄肩、收袖、窄长下摆 |
| C5 | 单件 | 内侍帽冠 | 紧凑、非武职、与官帽反差 |
| C6 | 单件 | 宽袖大礼袍 | T 型、大袖、长身 |
| C7 | 单件 | 帝王高冠 | 高、窄、纵向最高等级 |
| C8 | 套装候选 | 皇后大袖外衣 + 宽摆宫裙 | 横向大袖 + 大 A 字裙摆 |
| C9 | 单件 | 皇后大型冠饰 | 横向/纵向大体量 |
| C10 | 单件 | 多层宫廷外服 | 外层开放、内外长度差 |
| C11 | 单件 | 多层礼裙 | 两级或三级裙摆 |
| C12 | 单件 | 正式鞋履 | 介于布鞋和军靴之外的文职/宫廷轮廓 |

C1 的最新用户反馈已否定无腰筒形。H 型指克制的整体长轮廓，不要求胸腰等宽；必须有正侧面均能读出的真实腰线和几何束带。当前重做及未解决的动作问题见《C1窄袖直身长袍》，不得恢复旧水桶版的腰宽门槛。

队列可以由用户调整。调整顺序不改变本工作流的单轮边界。

## 五、每轮开始前

必须重新读取最新远端 `main`，不能用聊天里的旧 SHA 覆盖并行提交。

至少阅读：

- `AGENTS.md`
- `Documentation/工作交接.md`
- `Documentation/服饰版型目录.md`
- 本文件
- `Documentation/服装生成架构.md`
- `Documentation/固定基模与换装V5.md`
- 与本件最接近的现有服饰专题文档和作者代码

然后：

1. 确认本轮只处理一个单件或一个合格的小套装；
2. 在 `WARDROBE_GAPS` 中确认目标缺口；
3. 找出同槽位最近似资产；
4. 先写出至少两个结构差异维度；
5. 确认现有槽位能表达该资产，不为身份另开新槽位；
6. 创建独立分支和 PR。

不要先注册一批未来空 ID，不做占位选项。

## 六、实现边界

继续保持：

- Recipe V5 六字段、七槽位；
- 固定成年男女；
- 20 骨人物骨架；
- 每顶点最多双权重；
- 一个装配后人物网格；
- 玩家自由混搭；
- 三色染色只改色，不改变几何；
- 代码为实现权威；
- 不做实时布料、裙摆骨链、职业字段、阶级字段或宫廷玩法。

真正的长袍允许作者资产跨越 pelvis／thigh／shin 等区域，只要覆盖关系和动作验证明确；不能为了长衣新增另一套人物协议。与独立 bottom 同时穿着时必须用实际组合检查重叠和穿插，不能假设“上装只会到腰”。

如果某个设计只有成套时才合理，仍应尽量让部件保持独立可选；“推荐组合”不等于硬锁套装。

## 七、登记要求

完成真实作者资产后，同步更新：

- `src/character/v3/types.ts`
- 对应 `patterns.ts`／头饰分派／鞋履分派
- `SLOT_OPTIONS`
- `WARDROBE_TAXONOMY`
- 已被填补的 `WARDROBE_GAPS`
- 本轮必要的数值检查
- 对应专题文档或本工作流的进度记录

不允许新增正式 ID 却不登记 taxonomy；现有覆盖检查必须继续拦截。

## 八、数值与结构验收

每轮至少验证：

- TypeScript / production build；
- 网格闭合、非流形、退化面和坏权重；
- 男女固定基模；
- 20 骨与最多双权重；
- 染色不改变坐标、拓扑和权重；
- taxonomy 覆盖；
- 与最近似现有服饰的结构差异断言；
- 正常站立与适用动作下的真实蒙皮；
- 长摆／宽袖／高腰裙等涉及下半身时，运行相关贯穿检查；
- 不降低原采样、容差或已有故障注入门槛。

共享运行时未修改时，不因一件新衣服主动扩大成全项目重做。

## 九、视觉验收

新增服饰属于视觉变化，自动数值通过不能直接合并。

每轮必须生成并实际查看**针对本轮新 ID 的定向截图**。旧的 `review-wardrobe-batch` 第一批固定矩阵不能作为新宫廷服饰的视觉证据。

最低视觉证据：

- 男／女各至少一组；
- 正面；
- 侧面；
- 背面；
- 三分之四或自由视角；
- 统一灰色／素模轮廓；
- 与最近似现有服饰同机位对照；
- 至少一个日常动作；
- 对长摆、宽袖、裙装额外查看最容易暴露问题的动作相位。

如果是 2–3 件小套装：

- 每件至少有独立单穿图；
- 套装必须有组合图；
- 不能只展示最好看的最终整套而看不到单件问题。

关键截图必须在最终交付回复里直接展示；区分：

1. 自动检查通过；
2. 截图成功生成；
3. AI 实际打开看过；
4. 用户最终美术认可。

四者不能混写。

## 十、PR 与合并

推荐流程：

1. 分支完成作者资产；
2. 先跑针对本件的快速数值检查；
3. 开 PR；
4. 让 Build & Core Checks 和路径相关 Targeted Numeric Checks 跑完；
5. 生成本件定向视觉证据；
6. 实际查看关键截图；
7. 只修本件发现的问题；
8. 合并前重新读取最新 `main`；
9. 正常合并，不强推；
10. 确认合并后主分支基础检查；
11. 更新工作交接。

不要因为 Actions 尚在运行就不停高频轮询，也不能因此在“候选已提交”阶段提前结束。检查应在合理节点查询；若某条与本轮无关的大矩阵较慢，先继续完成能完成的审查与文档，最终仍以所需 Gate 通过后合并。

## 十一、完成定义

一轮只有同时满足以下条件才叫完成：

- 本轮范围没有扩张；
- 新资产是真实几何，不是旧资产换色/拉伸冒充；
- 至少两个结构维度与最近似资产明显不同；
- taxonomy / gap 已同步；
- 自动检查通过；
- 本件定向截图已经实际查看；
- 关键截图已准备给用户直接审查；
- PR 已正常合并到最新 `main`；
- 没有把用户美术认可伪写成自动验收结论。

下一轮再选择下一件或下一套，不在同一 PR 顺手继续。
