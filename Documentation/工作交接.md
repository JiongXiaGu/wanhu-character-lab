# 工作交接

这是新对话、新 AI 或新开发者接手 Wanhu Character Lab 时的首要入口。

## 项目定位

本仓库用于验证《万户天工》的程序化人物生成方案。

它不是最终 Web 产品，也不是独立角色编辑器产品。最终目标是把验证稳定的规则迁移到 Unity，用于大规模城市居民。

网页主要验证：

- 人体参数如何映射为运行时 Mesh；
- 服装如何从 Recipe 生成而不是加载成品模型；
- 骨骼、蒙皮、LOD、合并和缓存策略；
- 角色数据协议是否能被 Web 与 Unity 同时理解。

## 当前技术栈

- React
- TypeScript
- Vite
- Three.js
- Vercel：仅用于在线观察

正式 Unity 方向：

- Unity 6
- MeshData
- Burst / Jobs
- Entities
- SkinnedMeshRenderer 或后续验证后的 GPU 变形路径

## 当前阶段

当前为 Phase 1：HumanTopologyBlueprint / Ring Topology。

Phase 0 的 Sphere / Cylinder 人体只用于验证最小闭环，已经退出正式生成路径。

当前人体生成链：

`BodyParameters -> HumanTopologyBlueprint -> BodySection -> Ring -> BufferGeometry`

当前已做到：

1. 页面不加载 FBX / GLB 人物资产；
2. 身高、体型、肩宽、头部比例驱动 Ring 参数；
3. Torso / Head / Arms / Legs / Feet 全部由语义 Ring 生成；
4. Ring Builder 直接写顶点与索引，不依赖 Three.js 成品人体几何；
5. 最终仍然只有一个 BufferGeometry / Mesh；
6. 每个顶点带 `bodyRegion` 语义属性；
7. 页面可以切换 Wireframe 并观察 Section / Ring / Vertex / Triangle 数量。

## 核心规则

人体、衣服、裤子等正式方案默认走运行时生成。

仓库未来可以包含用于算法对照、测试或美术参考的资源，但不得退化成“每件衣服一个 FBX / GLB”的传统换装系统。

Web 与 Unity 的共享层是：

- 参数定义；
- Recipe；
- 拓扑语义；
- Region；
- Skeleton 语义；
- LOD 规则；
- Character Recipe JSON。

不是 Three.js 对象或 React 组件。

## 当前关键代码

- `src/App.tsx`：实验 UI、参数、Wireframe 和统计；
- `src/character/types.ts`：人物参数；
- `src/character/topology.ts`：拓扑语义；
- `src/character/createHumanTopologyBlueprint.ts`：参数转 Section / Ring；
- `src/character/buildTopologyGeometry.ts`：Ring 编译成顶点 / Index；
- `src/character/generateHumanoidGeometry.ts`：薄编排入口；
- `src/scene/CharacterViewport.tsx`：Three.js 场景与预览。

## 下一步

优先做 JointPatch，而不是服装。

顺序建议：

1. ShoulderPatch；
2. HipPatch；
3. NeckPatch；
4. 确定共享边界顶点语义；
5. 再开始 Skeleton / Skin Weight。

JointPatch 的目标是建立可持续拓扑规则，不是立即追求雕刻级人体。
