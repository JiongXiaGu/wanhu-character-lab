# 背部装饰与工具

## 外观与入口

B1扩充既有背部槽位：bamboo_basket竹背篓、firewood_bundle柴捆、book_case书笈，与none和原archer_quiver箭袋并列。人物工坊右侧展开「随身装备」，在「背部」选择；不新增槽位、页面、内容物编辑器或职业预设。

竹篓用宽口窄底、厚边和可见内壁表现容器，横向柴捆以五根错长木柴和两道绑绳表现劳动负重，窄高书笈以竹木框、三叠书册、布盖和绑带区分轮廓。一个选项包含完整主体与背带；没有把竹丝、绳结或书页逐一建模。书笈布盖跟随主布色，绑带跟随缘边色，木竹纸页保留材质色。

首批只有这三件，不顺带加入行囊、折伞、渔篓、背锄或背手切换。它们是外观资源，不代表居民职业、库存、负重容量或工作行为。

静态背面示例：?review=1&pose=bind&paused=1&view=back&back=bamboo_basket。back可替换为firewood_bundle或book_case；bodyType=female查看女性。

## 数据所有权与装配

Recipe仍是V5六字段、七slots；只扩充BackId与BACK_IDS。catalog提供中文名称并沿用严格文件校验、保存恢复、撤销、种子与锁定；randomizeCharacter按真实BACK_IDS抽取，不维护第二份背部目录。旧V5配方中的none和archer_quiver继续合法；旧程序不能识别新资产ID时仍应明确拒绝，不偷偷转换。

wardrobe/assets/back-accessories.ts拥有三件主体作者网格。所有主体点刚性绑定Chest，按现有shapeRigidPoint映射到固定男女基模。wardrobe/assets/back-harness.ts拥有两条闭合薄实体肩带，只在创建时向可见衣身/皮肤投影，并继承该表面的最多双权重。肩带先走shapePoint，主体后走shapeRigidPoint，不能混用两种映射，也不能以刚性背包权重拖动衣服。

makeCharacter将二者并入原surface，复用原SkinnedMesh、顶点色和20骨架。无新骨、单独Animator、逐帧网格重建、物理或IK。切换背部仍使用原换装生命周期；换动作复用网格，不重绑、不重算inverse bind。none完全不装配新主体和肩带，原箭袋路径保持。

主体三角形预算为竹篓156、柴捆176、书笈180；两条肩带共144，因此完整装备增量为300、320、324。逻辑点分别为主体80/98/112加肩带72，硬边渲染拆点另计。预算是当前作者结果，不代表Unity群体性能结论。

竹篓口视觉敞开，但外壁、口沿、内壁与内外底构成一张封闭壳。其他作者小壳和肩带均闭合、朝外，不使用双面材质或黑色盖片隐藏错误。主体不修改衣服covers，不按姿态删除皮肤或衣面。

## 检查与边界

npx tsx scripts/check-back-accessories.ts检查男女×全部八个上衣选择（含无上衣）×三件装备共48组合，闭合性、绕序、三角形预算、原人体/衣服/绑定不变、配方往返、随机与锁定，并保留删面、反面、错骨和坏配方等反例。

动作目录动态读取全部FBX、XR Animator与MediaPipe来源。慢跑、坐姿拨动开关、射箭、起步和Snatch检查全部源键与中点，其他动作检查九相位。通过实际SkinnedMesh顶点求值核对有限值、主体Chest刚性、包围球、几何复用和inverse bind稳定；这不是所有三角面、所有连续时刻的零穿插证明。

node scripts/check-back-accessories-browser.mjs默认只做真实桌面交互，涵盖切换男女、三件装备、none、旧箭袋、保存恢复、真实文件导出导入、未知ID拒绝、撤销、锁定、三种动作相位，以及骑乘页配方导入。--screenshots显式生成三件背面斜视、背带正面、竹篓俯视与女性坐姿六张关键图。报告记录实际受测SHA，生成截图、AI查看与用户美术认可分别记录。

Targeted Numeric Checks承载数字与桌面检查，Manual Visual Review增加back-accessories作用域，不新增永久工作流。当前容器本地构建和数值检查可执行，浏览器因环境策略不能访问本地页面，桌面交互和截图使用Actions；不能称作本地浏览器通过。

原服装、坐骑和动作回归不减少或放宽。大型背负物与强扭身、极限后仰、复杂坐具/鞍具的接触仍须视觉确认。Web允许导入骑手装扮，不代表已实现背包与所有鞍具的精确碰撞适配。没有职业绑定、装载/卸载、背手切换、容量、物理摆动或Unity正式运行时。
