# 万户 · 衣冠工坊 V5

《万户天工》玩家／居民角色换装与 FBX 试衣工作台。**两个固定男女基模，一种标准低模精度，重点是服饰丰富度与可靠换装。** 职业、导航、生产、战斗和场景交互留在 Unity。

## 使用

Node.js 22.12+；拉取 main，双击 `Start-Local.cmd`，或执行 `npm ci`、`npm run dev`。

左侧选男女基模和推荐搭配；右侧更换上衣、下装、头饰、鞋、发型、染色与随身装备；中央默认静态试衣。动作库支持中文／英文／文件名搜索、分类、收藏、上下一条与逐帧检查。坐姿拨动开关、射箭、慢跑和抓举深蹲继续作为重点验收动作。

## 当前：独立衣裤主路线

保留 Recipe V5，升级几何为 `wanhu-modular-garments-v2`。上衣、裤装和鞋是独立网格，程序按固定覆盖表装配裸露皮肤；裤装用有宽度的裆底连接，不复制原人体衣面。

现有7种上衣、7种下装及农户/卫兵/弓手全部接入同一路径。短袖、长袖、直裤与简化阔裤组成第一批固定版型；礼衣暂不代表完成的长袍/宫装。下一步在可靠版型上丰富款式，不扩大通用编辑器。

删除旧衣面扩张、裆点压缩、旧默认发髻生成后再删除路径。没有新旧服装切换或历史配方迁移。V5仍精确包含 `version/bodyType/slots/dyes/hairStyle/hairColor`，保存键 `wanhu.character.wardrobe.v5`；旧版、缺失和未知字段明确拒绝。

保留八套推荐、主要部件跨男女混搭、三色染色、发色/发式、种子、锁定、撤销、保存和文件导入导出。没有连续身高/胖瘦、LOD选择或体型适配编辑器。

## 动画与资源

FBX 放入 `动画参考/`（支持子目录），重启开发服务或重新构建自动扫描。当前扫描得到 23 份文件，数量不是上限。提取失败会报出文件，不能静默忽略，不恢复程序动作。用户的 FBX 及参考模型不修改。

20 骨骼语义与双权重保持；人体和衣服没有各自独立 Animator，不做实时布料、每帧碰撞或全身 IK。男女各自固定的绑定位置仍可能不同，不未经验证共用最终蒙皮矩阵。

## 验证与边界

执行 `npm run check:retired`、`check:mesh`、`build`、`check:mixamo`、`check:wardrobe`、`check:tailoring`。原五条Actions继续运行；新增Modular Garment Review生成基线/候选同相机图片、独立裤装近景、浅色和无光照/线框。

只在Actions runner启动预览生成截图，不部署Vercel/Visual。实际检查图片后合main，再由用户简单视觉复核。不录制视频，但保留真实播放结束和循环检查、原动作源键/中点采样及贯穿阈值。

人体与绑定黄金数据保持；旧人体复制衣面的表面哈希明确退役。PR #12失败补面不合入。独立裤装改造不是裸模修复，数值通过也不等于所有袖子、道具和连续姿态零穿插。实际受测SHA/Actions/看图范围见交接与PR。

本轮不是外部衣服导入器、Unity插件或GPU万人系统。不同新衣服可以有自己的拓扑与双权重，不要求套同一个人体形变公式。
