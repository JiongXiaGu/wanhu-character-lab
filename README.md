# 万户 · 衣冠工坊 V5

《万户天工》玩家／居民角色换装与 FBX 试衣工作台。**两个固定男女基模，一种标准低模精度，重点是服饰丰富度与可靠换装。** 职业、导航、生产、战斗和场景交互留在 Unity。

## 使用

Node.js 22.12+；拉取 main，双击 `Start-Local.cmd`，或执行 `npm ci`、`npm run dev`。

左侧选男女基模和推荐搭配；右侧更换上衣、下装、头饰、鞋、发型、染色与随身装备；中央默认静态试衣。动作库支持中文／英文／文件名搜索、分类、收藏、上下一条与逐帧检查。坐姿拨动开关、射箭、慢跑和抓举深蹲继续作为重点验收动作。

## 本次破坏性重构

- 删除连续身高／胖瘦及其 UI、配方字段和动画导出参数；不做多套体格模板。
- 删除 LOD0／LOD1 衣面细分、三级选择和兼容读取；原 LOD2 成为唯一标准精度。
- Recipe V5 只包含 `version/bodyType/slots/dyes/hairStyle/hairColor`；旧 JSON、缺失或额外字段均明确拒绝，不自动迁移。
- 浏览器保存使用独立的 `wanhu.character.wardrobe.v5`，不读取旧存档。旧浏览器数据不主动删除，但不会恢复到新模型。
- 删除旧 outfit／hat／equipment URL 入口、旧配色编号、auto 发型及旧数据迁移。基础农户／卫兵／弓手仍作为可编辑服饰组合，不作为玩法身份。
- 新增固定版型数据 `wardrobe/patterns.ts`，从服装生成逻辑中分离尺寸与袖口等美术定义。

八套推荐不是八个固定角色；服饰不按性别、职业锁定。保留三色染色、三种发髻、随机种子、部件锁定、撤销、保存及严格导入导出。

## 动画与资源

FBX 放入 `动画参考/`（支持子目录），重启开发服务或重新构建自动扫描。当前全部23份文件进入目录和检查。提取失败会报出文件，不能静默忽略，不恢复程序动作。用户的FBX及参考模型不修改。

20骨骼语义与双权重保持；人体和衣服没有各自独立Animator，不做实时布料、每帧碰撞或全身IK。男女各自固定的绑定位置仍可能不同，不未经验证共用最终蒙皮矩阵。

## 验证与边界

运行 `npm run check:retired`、`check:mesh`、`build`、`check:mixamo`、`check:wardrobe`、`check:tailoring`。五条 GitHub Actions 输出真实截图与连续视频，下载审查后才合 main。只在runner内启动预览，不部署Vercel。

**这轮是换装系统重构，不是髋裆美术修复。** 以main `4740a5c` 原LOD2为基线，16个男女推荐组合的身体、衣面和绑定哈希必须一致；不合入PR #12未通过深蹲的补面。原有髋下暗面、裤式分叉观感、侧面偏薄和膝部硬折仍需下一阶段局部重建。数值无贯穿不等于全部姿势与配件零穿插。

后续允许修正基模拓扑／权重，但须明确升级资源版本并审查，不再以历史顶点完全不变为永久限制。先修好固定男女，再扩充成熟服饰版型，不恢复连续体型。
